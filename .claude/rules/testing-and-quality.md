# 验证门与质量底线（防质量漂移）

> 项目特定的测试与质量要求。通用反模式禁令（上帝类、长方法、复制粘贴、魔法值、吞异常、资源泄露、循环依赖、静态可变单例等）仍然适用。

## 1. 验证门（权威判据）
- **每个变更必须过验证门才算完成**，判据以**入库真源**为准：① `docs/PRD.md` 验收标准对应项满足；② 本文 §2 高风险区相关测试通过；③ 受影响组件全部测试绿（各组件按本项目实际的测试 / 构建命令执行）。
- **完成以证据为准、不轻信报告**：声称"做完 / 修好 / 通过"前，必须出示上述各项的客观证据（命令 + 关键输出、失败用例从红转绿、有实机 / 集成 / 真实环境维度的附该维度复验结果）。拿不齐 = 未完成、继续做——不轻信任何"完成了"的口头报告（含子代理的汇报）。
- **被推翻就回流继续修**：声称完成后被实测 / 实机 / 用户验收推翻，即视为该变更未完成，**回到本任务对应技能的验证步骤继续修**，不另开新流程、不重标状态。
- **提交受验证门门控**：验证门未全绿不得 `git commit`（门控见 `git-commit.md` §3）。
- `.tmp/` 下实施计划的里程碑勾选**仅作开发期辅助**，不入库、不作权威判据（clone 后可能不存在）。
- **禁止**以注释、跳过、删除失败测试的方式让测试"通过"。
- 改功能代码前先跑相关测试确保通过；新增 / 改业务逻辑同步加测试。

### 1.1 测试分层（怎么分、在哪跑）
- **单元**：纯逻辑（核心算法 / 纯函数）—— 不连外部依赖，最快最多。
- **集成**：被测组件 + 真实外部依赖（测试库 / 容器）跑关键流程。
- **E2E**：按本项目编排（如 compose）拉起完整依赖，跑关键时序（见 ARCHITECTURE §6 关键机制与 PRD 验收）。
- **何时跑**：单元 / 集成随每次改动与 CI；E2E 在发版前至少跑一遍。

## 2. 必测的高风险区

- **授权矩阵**：穷举 匿名 / 普通用户 / 仓库 ACL 用户 / Admin × public/private 可见性 × read/write/admin 动作 的全组合；被禁用用户、被撤销会话、被吊销 Token 的下一次请求必定失败。
- **group 聚合零泄露**：先校验 group read，再只聚合调用方有 read 权限的成员；穷举"可读 group + 部分成员可读""可读 group + 全部成员不可读""不可读 group"三类场景，任何响应不得泄露无权成员的名称、坐标、版本、dist-tag、数量或错误原因。
- **blob 写入提交顺序与提交守卫**：写入必须按"临时写入 → 校验 → 原子提交 blob → 提交元数据"推进；穷举各步中断（进程终止、磁盘不足、DB 提交失败、断流），不得留下可见半成品索引；临时文件可识别、可回收、不被正常读取路径命中。
- **路径规范化与越界防护**：穷举 `..` 回溯、编码绕过、绝对路径、空段等恶意路径样本，全部拒绝且不越出仓库根。
- **迁移状态机与幂等续传**：穷举任务状态机（queued/running/pausing/paused/cancelling/cancelled/succeeded/partial/failed/interrupted）的合法与非法迁移；服务重启后在途任务判"已中断"；重跑只处理未完成 / 失败 / 变化对象，已一致对象精确计为跳过，不产生重复索引或孤儿 blob。
- **凭据处理**：密码、Token、JWT 密钥、Nexus 凭据在任务参数快照、数据库、前端响应、日志、报告中均不得出现明文；Token 明文只在签发时出现一次。
- **proxy 单飞合并并发**：同一 proxy 仓库同一路径的并发缓存未命中只产生一次有效上游拉取；上游不存在 / 超时 / 4xx/5xx / 断流按类别正确传播且不污染缓存。

## 3. 质量底线
通用反模式底线（任何项目都适用）：
- 分层依赖单向、不反向穿透（防上帝类 / 防泄漏底层细节到上层）。
- 锁 / 临界区职责单一、不嵌套，高开销 IO 一律在锁外。
- 核心计算尽量做成无副作用纯函数，便于穷举测试。
- 多处写操作必须在事务内原子完成，**事务提交成功后**才触发对外副作用（通知 / 唤醒 / 发事件）。
- 中文分级日志（ERROR/WARN/INFO/DEBUG），不留 `println!` / `console.log` 等临时调试输出。
- 不硬编码凭据 / 端口 / 超时等，走配置或常量。

> 更具体的架构红线（分层名、依赖方向、并发与存储约定）见 `architecture-invariants.md`。
