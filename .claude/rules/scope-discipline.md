# 范围纪律（防范围漂移 / 镀金）

> 依据 `docs/PRD.md` 的分期。**只做当前阶段该做的，不提前做、不顺手做。**

## 1. 第一期（M1）只做

- 多用户认证与本地授权：管理员自举、用户名密码登录、会话刷新与即时撤销、API Token（明文只显示一次、持久化只存哈希）、CLI 鉴权（Basic / Bearer）、用户管理（Admin/User 角色、禁用即时生效）。
- 仓库模型与权限：public/private 可见性（private 对无权用户不泄露存在性）、仓库级 read/write/admin ACL、仓库创建 / 编辑 / 停用 / 删除（区分"仅删配置"与"删除数据"）。
- 三格式 × 三类仓库：Raw、Maven、npm 的 hosted、proxy 与只读 group（只聚合调用方可读成员、零泄露）。
- 原生客户端互通：curl、Maven、npm 直接发布 / 代理 / 下载。
- 管理端 Web：登录、仪表盘、仓库列表 / 详情与文件浏览、用户管理、Token 管理、迁移向导、迁移任务与报告、使用方式片段。
- Nexus OSS 3.70.x 仓库全量迁移：在线 / 离线发现、迁移计划预览、hosted / proxy / group 迁移、异步任务状态机、持久化与重启恢复、幂等增量续传、迁移报告、凭据安全、冲突策略、离线迁移包导出。
- 健康检查（不泄露路径、凭据或内部拓扑）。
- 开发支撑：devmock 场景包、wiki 组件验收站。
- 构建部署与前端工程化：Makefile 统一构建入口与 Docker 内 Linux 发布构建、SSH + systemd 部署脚本、前端四子工程基座与严格静态检查接线。

> 权威边界以 `docs/PRD.md` §4 FR 登记册为准（本清单是其摘要）；新需求经登记流程进入 PRD 后即属边界内，未登记的能力一律越界。

## 2. M1 严禁出现（属后续阶段）

- **M2（高频格式扩展）**：Docker/OCI、Cargo sparse registry、PyPI、Go modules proxy、NuGet、全局跨仓库搜索。
- **M3（企业认证 / 存储 / 运维）**：OIDC / LDAP、用户组与更细粒度权限、S3 兼容对象存储、审计日志与 Prometheus 指标、备份与恢复、GC / 保留策略 / 配额。
- **M4（安全 / 供应链 / 运营可见性）**：多维限流与慢速请求防护、IP 名单与应用层防护、漏洞库镜像与坐标匹配 / 镜像层扫描、使用分析与容量趋势。
- **M5（长尾格式与成熟期）**：RubyGems / Conan / Terraform / Ansible Galaxy / Dart Pub 等长尾格式、高级虚拟仓库策略、多节点 / 高可用方案、外部数据库或分布式存储。

一旦在代码 / 数据模型 / 契约里看到上述能力的提前实现或占位字段 → **删除，或停下来问**，不得镀金。

## 3. 不为未来预留空壳
- 不写"以后可能用"的抽象、配置项、接口、字段。需要时再加。
- 后续阶段能力到时按域新增包，当前不留占位。

## 4. 越界先问
- 若某任务看起来需要某个后续阶段能力才能完成 → **停止并向用户确认**，不自行扩大范围。
- 简洁方案优先：实现远多于必要（如 200 行 vs 50 行）时重写。资深工程师会觉得过度复杂的，就是过度。
