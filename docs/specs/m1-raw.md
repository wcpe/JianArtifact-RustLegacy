# 功能规格：Raw 协议——hosted 与 proxy（M1-FR-013~014）

> 状态：已批准 / 开发中　·　关联 PRD：M1-FR-013、M1-FR-014　·　分支：main 直接提交，按域三步工序推进（ADR-0014）

## 1. 背景与目标

属 M1，三格式中最薄的协议层：Raw 仓库把任意路径直接映射到通用 hosted/proxy 机理（`m1-repository-core.md` FR-010/011），是首个端到端可验收的格式，也是 NFR 大文件验收（5 GiB 样本）的载体格式。本规格只定义 Raw 特有的 HTTP 协议行为；鉴权、路径规范化、提交守卫、单飞、错误分类等一律引用通用层，不重复定义。

## 2. 需求（要什么）

**FR-013 Raw hosted**

端点空间 `/repository/{仓库名}/{路径...}`，HTTP 语义：

- `PUT {路径}`（write 权限）：请求体流式写入（走通用四步提交守卫）；新路径返回 201；已存在路径按仓库覆盖策略——allow 时替换（旧 blob 失去引用即回收）返回 200，deny 时返回 409 冲突。
- `GET {路径}`（read 权限）：流式返回内容；`Content-Type` 按扩展名推断（未知为 `application/octet-stream`）；返回 `X-Checksum-Sha256`、`X-Checksum-Sha1`、`X-Checksum-Md5`、`X-Checksum-Sha512`，并以 SHA-256 作为强 `ETag`。
- `HEAD {路径}`：与 GET 相同的状态码与头，无响应体（curl -I 与探测场景）。
- `DELETE {路径}`（write 权限）：删除成功 204，路径不存在 404；blob 回收走通用引用检查。
- `GET {目录路径}/`（read 权限，以 `/` 结尾）：返回 JSON 目录索引（条目名、是否目录、文件大小、更新时间），分页遵循 NFR-16；仓库根 `/repository/{仓库名}/` 是根目录索引；不提供 HTML 目录页（管理端有文件浏览 UI，FR-019）。
- 规范化后的 UTF-8 路径最长 4096 字节；对象路径不得为空或以 `/` 结尾，PUT/DELETE 不接受目录路径。
- hosted 请求可携带 query string，但 query **不参与路径键、索引键或缓存键**；同一路径不同 query 读写的是同一对象。
- 路径安全、大小上限（NFR-01）、缓冲（NFR-02/03）、磁盘阈值（NFR-11）全部继承通用层。

**FR-014 Raw proxy**

- `GET`/`HEAD`（read 权限）：缓存命中本地流式返回；未命中按仓库、路径与 `upstream_url` 配置快照单飞合并回源 `上游 URL + 路径`（拼接时规范化斜杠），2xx 响应先按通用四步完整流式落盘并原子提交正缓存，再由本地 blob 流式响应，以保证首次请求与缓存命中的校验和头一致且失败不发送半截成功响应；配置更新前后的同路径请求属于独立单飞任务，回源任务独立于首个客户端，HEAD 未命中同样触发完整回源缓存。
- 正缓存提交必须在同一事务内核对仓库仍为 proxy 且当前 `upstream_url` 等于回源预期快照；旧配置提交被拒后，按原主体和仓库名重新执行授权读取并按新配置最多透明重试一次。若配置连续变化导致第二次提交仍被拒绝，则返回稳定 503，不无限回源且不写入旧缓存。
- 上游允许指向内网、环回与链路本地地址，以支持自托管制品源；URL 禁止 userinfo、控制字符与 fragment。客户端禁用自动重定向，任何 3xx 映射为 502，凭据只发送到已配置的初始目标。
- 上游错误按通用五类传播，Raw 层的对外映射：上游 404 → 404；连接失败/超时 → 504；上游其他 3xx/4xx 与 5xx → 502（错误体含稳定类别与中文消息，不含上游凭据）；转发中断时未提交的缓存临时文件回收。
- 写操作（PUT/DELETE/POST）→ 405（proxy 只读）。
- 带 query string 的请求 → 400 拒绝（中文错误说明 Raw 代理按纯路径寻址；见 §6 评审点）。
- 缓存键 = 规范化路径；`Content-Type` 与 hosted 同规则按扩展名推断，不存储上游头（见 §6）。

## 3. 设计（怎么做）

- 模块落点：`protocol/raw`——只做「HTTP 语义 ↔ 通用机理」的映射与状态码翻译，禁直连数据库（ADR-0006）；经 Format 注册表挂载。
- 新增依赖：`mime_guess`（按扩展名推断 Content-Type，纯 Rust 无 C 依赖；按规则 15 经本规格评审确认）。
- 格式端点同样以 utoipa 注解纳入 OpenAPI（独立 tag），但 devmock 不模拟格式端点（其契约面向管理 API，FR-035）。
- 三步工序：阶段 1 契约骨架（路由 + 模型注解）→ 阶段 2 无本域特有前端页面（文件浏览由仓库核心页面覆盖）→ 阶段 3 后端实现（依赖通用 hosted/proxy 机理落地，作为其首个消费方联调）。

## 5. 验收标准

对照 PRD §6.2「Raw hosted / Raw proxy」与 NFR：

- **协议测试（容器内自动化）**：PUT 201 / 覆盖 allow 200 与 deny 409 / GET 字节一致且 Content-Type 正确 / HEAD 与 GET 头一致 / DELETE 204 后 GET 404 / JSON 目录索引含刚上传条目且分页正确；匿名对 public 只读、对 private 零存在性泄露（复用通用矩阵样本在 raw 端点抽查）；恶意路径样本全部拒绝。
- **proxy 协议测试**：首次 GET 回源恰一次（单飞 32 并发对同一 raw 路径验收，NFR-08）；更新 `upstream_url` 时，新请求不等待旧配置 flight，旧回源提交被拒后按新配置最多重试一次并返回新内容，后续缓存中不存在旧内容索引；连续配置变化耗尽一次重试时稳定返回 503。上游 404/超时/4xx/5xx/断流五类各返回既定状态码且缓存无残留；PUT→405；带 query→400。
- **真机维度（需用户确认，隔离环境原生 curl）**：上传→下载→覆盖→删除全流程；proxy 首次回源后**断开上游**再次 GET 命中缓存；上游停服时错误类别正确。
- **NFR 大文件验收（本格式为载体）**：5 GiB 样本经 raw hosted 上传/下载、raw proxy 回源，RSS 增量 ≤ 256 MiB、峰值 ≤ 1 GiB，输出 cgroup 证据（NFR-01/02/06）。

## 6. 风险 / 待定

- **query string 一律 400**：制品路径寻址不需要 query；若未来要代理带签名参数的上游，需引入直通不缓存模式——按新需求登记，不预留。
- **不存储上游 Content-Type**：缓存命中与首次回源的响应类型都按扩展名推断，保证两次一致；无扩展名文件将得到 `application/octet-stream`（评审点：如需保真上游头，需给缓存加元数据字段，属数据模型变更）。
- HEAD 未命中触发完整回源是有意取舍（避免 HEAD/GET 两套上游语义），大对象上的首次 HEAD 代价与 GET 相同——使用片段（FR-020）不引导用 HEAD 探测。
