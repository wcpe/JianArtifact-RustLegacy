# 功能规格：离线迁移包格式与导出（M1-FR-041 + FR-023 包格式本体）

> 状态：草拟　·　关联 PRD：M1-FR-041（导出）、M1-FR-023（离线发现读取的包格式本体）　·　分支：main 直接提交，按域三步工序推进（ADR-0014）

## 1. 背景与目标

属 M1。定义 JianArtifact 自有的**完整离线迁移包**格式与其导出流程，是 `m1-nexus-migration.md` 离线入口（FR-023 发现、FR-025~027 执行）的输入契约。决策依据 ADR-0008（离线迁移包）。核心是**一致性快照**——包内仓库配置、group 成员、proxy 上游、资产/缓存清单、blob 必须同属一个已验证快照，跨快照混用必须阻断。本规格定义包的物理结构、清单模式、校验规则与两种导出路径；发现读取与迁移执行编排见迁移规格，不重复。

## 2. 需求（要什么）

**FR-023 包格式本体（读取契约）**

完整离线迁移包是一个目录树（可打成单 tar，解包即目录），结构：

```
{包根}/
├─ manifest.json          # 权威清单（版本化，带整体摘要）
├─ repositories/          # 每仓库一个配置文件（含 group 成员、proxy 上游引用）
├─ assets/                # 每仓库资产/缓存清单（对象→blob 摘要映射，分片可跨多文件）
└─ blobs/                 # 内容寻址 blob 本体（sha256 前两位分桶，与本服务 blob 布局同构）
```

- `manifest.json` 必含：`format_version`（包格式版本，读取方按其决定解析规则，未知版本拒绝）、`source_instance_id`（源 Nexus 实例标识）、`snapshot_time`（一致性快照时间）、`nexus_version`（须 3.70.x，否则标实验性/阻断）、`repositories` 索引（名/格式/类型/对象数/字节数）、`overall_digest`（覆盖清单+全部资产清单+全部 blob 摘要的整体摘要）。
- **完整包 vs 裸 blob 判定**：具备 manifest + repositories + assets 的为完整包；只有 blobs（无权威清单）的为裸 blob store，走 FR-023 尽力恢复降级（迁移规格 §2），任务总状态不得全量成功。
- 敏感数据铁律：proxy 上游凭据在包内**只存引用名**，绝不含明文（导出方即使能读到 Nexus 凭据也不写入包）。

**校验规则（读取时，任一不过即整体拒绝导入，不做部分导入）**

- `format_version` 未知 → 拒绝并提示升级。
- `nexus_version` 非 3.70.x → 按矩阵外阻断或标实验性（ADR-0007）。
- **整体摘要校验**：重算清单+资产清单+blob 摘要的 `overall_digest`，与 manifest 记录不符 → 拒绝（防篡改/损坏/跨快照拼接）。
- **交叉引用完整性**：每个资产清单条目引用的 blob 摘要必须存在于 `blobs/` 且内容 sha256 与声明一致；group 成员、proxy 上游引用必须在 `repositories/` 内可解析；悬空引用 → 拒绝。
- **跨快照混用阻断**：所有部分的快照归属必须一致——资产清单/blob 与 manifest 的 `snapshot_time`、`source_instance_id` 绑定校验；故意混入另一快照的清单或 blob 会被整体摘要或交叉引用校验拦下。

**FR-041 离线迁移包导出**

- 导出源：连接一个 Nexus OSS 3.70.x 实例，在**源端停写/只读窗口**，或经「首轮导出 + 最终增量核对」，生成同一一致性快照的包。
- 导出流程：枚举仓库配置与成员 → 拉取资产/缓存清单 → 流式拉取 blob 内容寻址落 `blobs/` → 生成资产清单 → 计算并写入 `overall_digest` 与 `snapshot_time`/`source_instance_id`/`nexus_version` → 封包。
- **失败不得产出可误用的完整包**：导出中断/校验不过 → 不写出 manifest（或写出明确标记的 `.partial`），使不完整产物无法被读取方当作完整包导入。清单最后写、整体摘要最后算——manifest 存在即代表包已完整封定。
- 导出全程流式（大 blob 不整体入内存，NFR-02/03），凭据不入包不入日志。

## 3. 设计（怎么做）

- 模块落点：`migration/offline`——`PackageReader`（校验+读取，供发现器 FR-023）与 `PackageExporter`（导出，FR-041），共用 `manifest` 模型与摘要算法。经三格式领域服务无关（离线包是数据搬运格式，不涉协议语义）。
- blob 布局与本服务同构（sha256 前两位分桶），导入时可直接按内容寻址落定，天然幂等去重（同 blob 只存一份）。
- `overall_digest` 算法：对「排序后的 (仓库配置摘要 ⧺ 资产清单摘要 ⧺ blob 摘要)」做 sha256（确定性、可增量、可重算）；具体拼接顺序在实现时定稿并写入格式版本文档，避免跨实现漂移。
- 导出的「最终增量核对」复用迁移在线增量的漂移检测（迁移规格 §3）：首轮导出后对比源现状，零漂移才封定，否则要求重新进入停写窗口。
- CLI/入口：导出为独立子命令（`jianartifact` 二进制的迁移导出模式）或管理 API 触发的任务，二选一在实现时定（倾向 CLI，因导出常在源端离线环境跑，见 §6）。
- 依赖：tar 打包用纯 Rust `tar` crate（按规则 15 经本规格评审确认，无 C 依赖）；摘要用已引入 sha2；JSON 用 serde_json。
- 三步工序：本域无独立前端页面；向导的离线入口**手填服务器上的包路径**（后端按 `migration-workdir` 白名单根校验，不上传大包、不浏览文件系统，机制见 `m1-nexus-migration.md` §3）；阶段 1 契约（离线源在发现端点的参数模型，路径为字符串字段）→ 阶段 3 Reader/Exporter 实现。

## 5. 验收标准

对照 PRD §6.3 第 1、2 条与 §4.3 离线来源完成定义、`testing-and-quality.md` 高风险区：

- **格式与校验纯函数**（合成 fixture）：合法完整包通过；未知 `format_version`、`overall_digest` 不符、悬空 blob 引用、悬空成员/上游引用、非 3.70.x 各自被拒绝并给对应中文原因。
- **跨快照混用阻断**（PRD §6.3 第 2 条，核心）：完整快照可导入；故意把另一快照的资产清单或 blob 混入 → 整体摘要或交叉引用校验阻断，不产生部分导入。
- **完整包 vs 裸 blob**：完整包全量迁移；裸 blob store 仅尽力恢复（能归属三格式路径的迁移，无权威配置的标「配置待补充」），任务总状态不得全量成功。
- **导出一致性**：停写窗口导出的包整体摘要自洽、可被 Reader 导入；导出中断 → 不产出可当完整包导入的产物（无 manifest 或明确 .partial）。
- **导入幂等**：同一离线包导入两次，第二次全部对象计校验一致跳过，无重复索引无孤儿 blob（复用迁移 FR-030 口径）。
- **凭据零泄露**：导出的包内、导出日志均无明文上游凭据（只存引用名）；导入时缺引用的 proxy 标「配置未完成」。
- **流式导出/导入**：大 blob（对齐 NFR-01 的 5 GiB 样本）导出与导入的缓冲上限固定，输出峰值内存证据。
- **真机维度（需用户确认）**：在真实 Nexus OSS 3.70.x 停写窗口生成完整包 → 在纯离线环境（断开源）导入并全量迁移 → 三格式官方客户端验收（PRD §6.3 第 1、2、9 条）。

## 6. 风险 / 待定

- **导出入口形态（评审点）**：倾向独立 CLI 子命令（源端常是离线/受限环境，不便跑完整服务与管理 API）；但也可作为管理 API 任务。二选一影响交付形态，开发前定；无论哪种都不违反单二进制交付（同一 `jianartifact` 二进制的不同模式）。
- **`overall_digest` 拼接顺序**必须在格式版本文档里钉死并随 `format_version` 冻结——跨版本改算法即 bump format_version，旧包按旧规则校验（不可变契约）。
- **裸 blob 尽力恢复的归属准确性**：仅凭 blob 内容与路径线索推断格式归属，Maven/npm 可从内容结构辅助判定，Raw 几乎只能靠 blob store 内的路径属性——不可判定的一律入「不可识别」清单，不猜测（零误报优先）。
- 导出的「最终增量核对」同样依赖源端停写窗口这一操作约束（同迁移在线一致性），工具只保证窗口内零漂移才封包。
- tar 打包为可选封装（目录树本身即可用）；是否强制单文件 tar 在实现时定，验收以目录树语义为准。
