# 功能规格：Nexus 仓库全量迁移（M1-FR-022~034、037~040）

> 状态：草拟　·　关联 PRD：M1-FR-022~034、037、038、039、040；§4.3 完成定义为验收真源　·　分支：main 直接提交，按域三步工序推进（ADR-0014）

## 1. 背景与目标

属 M1，最大最硬的域：从 Nexus Repository OSS 3.70.x 全量迁移 Raw/Maven/npm 的 hosted/proxy/group 仓库到本服务。决策依据 ADR-0007（迁移策略）、ADR-0009（任务持久化）、ADR-0015（**默认离线直读 Nexus 原生数据目录**，在线 REST 降为备选、配置经 REST 或手动补）。自有离线迁移包（可选归档）的**格式与导出**由 `m1-nexus-offline-package.md` 定义，本规格聚焦发现→计划→执行→状态机→持久化→续传→冲突→凭据→报告→切换的全链路编排。**迁移落库经三格式协议的领域服务，产出必须满足 raw/maven/npm/group 各规格的客户端可观察语义**（不绕过协议层直写）。

范围铁律（scope-discipline）：只迁**仓库数据**，不迁 Nexus 用户/角色/权限/脚本/计划任务/系统配置；矩阵外版本/后端/格式必须显式阻断或标实验性，不静默按 3.70.x 处理。

## 2. 需求（要什么）

**FR-022 在线发现 / FR-023 离线发现**（三类来源，默认离线直读，见 ADR-0015）

- **离线直读 Nexus 原生数据目录（首选，直接迁移、无需打包）**：解析磁盘上的 Nexus 文件型 blob store——遍历 `.properties`（含归属仓库、路径/坐标线索、sha1、大小、内容类型、删除标记）配对 `.bytes`，据此归属并枚举可迁对象；数百 GB 的 blob 全程磁盘直读、不过网。仓库配置（proxy 上游、group 成员）两种来源：Nexus 可达时经 REST 一次性拉取，已下线时由管理员在向导手动补（FR-039）。**不直读 Nexus 内嵌配置库**（H2/OrientDB 为 JVM 私有格式，纯 Rust 不可行，见 ADR-0015 备选）。原生数据目录一致性由「迁移前停 Nexus 或取文件系统快照后再拷/挂载」保证（操作约束，写入运维文档）。
- **在线 REST（备选，数据不在本机但 Nexus 可达时）**：经 Nexus REST 枚举仓库配置、成员关系与可迁制品清单（组件分页遍历，NFR-16 口径，遍历无重漏），直接搬运落库。
- **自有完整离线迁移包（可选归档）**：读取 `m1-nexus-offline-package.md` 定义的自有格式包，校验清单与 blob 完整性。
- **裸 blob store 降级**：仅有 blob、既无 REST 也无手动配置时——只迁能明确归属 Raw/Maven/npm 路径的内容（hosted 与已缓存内容），不猜 proxy 上游与 group 成员，无权威配置的仓库标「配置待补充/不可全量迁移」，任务总状态不得为全量成功。
- 发现阶段先做兼容性检查：非 3.70.x、非文件型 blob store、非三格式一律阻断或标实验性。
- **磁盘位置在 Web 指定**：向导离线入口（原生数据目录或自有包）不上传大数据、不浏览服务器文件系统，而是**手填服务器上的路径**（Nexus 数据目录路径或包路径），由后端校验——必须落在配置的迁移工作目录根 `migration-workdir` 之内（经 core 的路径规范化与越界防护，越界一律拒绝）、存在且可读；校验通过才进入发现。工作目录根由服务配置指定，未配置时离线入口不可用并给中文提示。

**FR-024 迁移计划预览**

- 执行前展示：源→目标仓库映射、重命名、冲突、类型、上游、凭据引用状态、成员关系、对象数、字节数、不支持项；给出目标空间估算（NFR-12：源估算 × 1.1 + 磁盘保留量），不足则明确警示。计划是可确认的预览，确认后固化为任务的不可变参数快照。

**FR-025 hosted / FR-026 proxy / FR-027 group 迁移**

- hosted：迁移全部受支持对象，**资产字节校验**（源字节↔目标字节 sha256 一致）与**协议元数据不变量**（各格式 metadata/sidecar/packument 独立通过校验，经协议层落库而非搬运原始 metadata 文件）分别验证。
- proxy：迁移上游配置、凭据引用状态、**全部可枚举正缓存**（逐对象迁移/校验/或明确列为未迁移，不以抽样代全量）；负缓存与瞬态 HTTP 状态不在范围。缓存对象落为目标 proxy 的正缓存。
- group：创建目标 group 并**保成员顺序**；成员缺失或不支持时**阻断该 group 完成**（不产出半成品 group）；迁移后按 `m1-group.md` 各格式语义客户端验收。

**FR-028 异步任务 + 状态机**

- 迁移请求立即返回 `task_id`（202），后台执行。状态机十态：`queued → running`；`running ⇄ pausing → paused → running`；`running/paused → cancelling → cancelled`；`running → succeeded | partial | failed`；进程异常中断在重启后判 `interrupted`。合法迁移与非法迁移（如 `succeeded→running`）都要测。
- **succeeded 严判**（§4.3 完成定义）：仅零显式排除（放弃）、零未迁移受支持对象、零未解决配置项时可 succeeded；任何放弃/缓存不可迁移/凭据未映射/配置不完整 → `partial` 并逐项计数。管理员显式排除的仓库保留在报告中，不伪装成从未发现。

**FR-029 持久化 / FR-030 幂等续传**

- 任务、不可变参数快照、节流进度、对象检查点、分仓报告、有界失败样本落 SQLite（ADR-0009）；服务重启后在途任务标 `interrupted`。
- 幂等键 = 稳定源标识 + 目标路径 + 内容校验（sha256）。重跑只处理未完成/失败/变化对象，已一致对象**精确计为跳过**（迁移数为零、不产生重复索引或孤儿 blob）。

**FR-031 报告 / FR-032 凭据安全 / FR-033 不支持项**

- 报告：按任务和仓库给出总数/完成/迁移/已存在跳过/失败/总字节/完成字节/耗时/失败原因/省略数量；失败样本有界（超出只计数，防膨胀）。
- 凭据安全：Nexus 凭据只经安全运行时引用获取；任务参数快照、数据库、前端响应、日志、报告均**不得出现明文凭据**（高风险区强制断言）。
- 不支持项：非三格式、非仓库系统数据列入「不支持/未迁移」清单，禁止静默丢弃或误报成功。

**FR-034 Web 迁移向导**

- 源配置→发现→选择与映射→计划确认→执行→进度→报告完整流程，刷新页面可找回（状态来自持久化，不靠前端内存）。向导 UI 属阶段 2 对 devmock 开发（正常/中断/部分失败/大任务场景）。
- 源配置步支持三类源：**离线原生数据目录**（首选，手填 Nexus 数据目录路径 + 选配置来源：REST 一次性拉 / 手动补）；**在线 REST**（填 Nexus 地址与凭据引用）；**自有离线包**（手填包路径）。路径类源一律按上文白名单根校验。三类源之后的发现/映射/计划/执行/报告步骤一致；手动补配置时向导提供 proxy 上游地址与 group 成员的录入表单（FR-039）。

**FR-037 在线一致性与切换 / FR-038 冲突策略 / FR-039 上游凭据映射 / FR-040 提交与控制边界**

- FR-037：首轮清单固化源快照时间；「首轮搬运 → 源端停写/只读 → 最终增量扫描」；只有最终扫描零未处理漂移（新增/修改/删除）才可全量成功。**默认不自动传播源端删除**，删除项在切换报告显式列出、由管理员决定。
- FR-038：默认禁止覆盖；同路径同校验→跳过；同路径不同校验→阻断，要求显式重命名/映射空目标/放弃；决策写入任务快照与报告。
- FR-039：不自动恢复 Nexus 明文/加密凭据；管理员为需认证 proxy 提供安全运行时引用（core FR-011 机制），缺有效引用的仓库状态「配置未完成」。
- FR-040：暂停/取消只在**单对象原子提交边界**生效；取消清理未提交临时文件但不删已成功且被引用的数据；重试只处理失败/中断/变化对象。

## 3. 设计（怎么做）

- 模块落点：`migration`——发现器（**Nexus 文件型 blob store 磁盘解析器** / 在线 REST 客户端 / 自有包读取器，共用「源清单」抽象）、配置源（REST 拉取 / 向导手动录入，产出 proxy 上游与 group 成员）、计划器（映射+冲突+估算，纯函数产出计划）、执行器（对象级迁移循环 + 提交边界控制）、状态机（纯函数：当前态+事件→新态，非法转移拒绝）、报告器；经三格式领域服务落库，禁直连协议层与数据库以外的旁路。
- Nexus blob store 解析：`.properties` 为纯文本键值（`@Bucket.repo-name`、`@BlobStore.blob-name`、`sha1`、`size`、`deleted` 等），解析为无 IO 纯函数（可对官方样例穷举测试）；`.bytes` 流式读入走 core 四步提交。deleted 标记的 blob 跳过。不依赖 Nexus 运行、不读其内嵌库。
- 数据表草案（ADR-0009，权威以迁移脚本为准）：`migration_tasks`（id、status、params_snapshot(JSON,含冲突决策与快照时间,凭据仅存引用名)、source_kind(online/offline)、created_at、updated_at、interrupted_at）、`migration_task_repos`（task_id、source_repo、target_repo、type、totals、done、migrated、skipped、failed、bytes_total、bytes_done、status）、`migration_failures`（task_id、repo、object_key、category、message，有界）。
- 幂等与提交守卫复用 core 的 blob 提交顺序：每个对象走「临时→校验→内容寻址落定→索引」，检查点在对象原子提交后记录；中断后重启从检查点续。
- 流式与并发：单对象流式（缓冲 NFR-02/03，禁整体入内存）；迁移对象并发 NFR-09（默认 4、上限 8），不挤占正常上传/下载/代理；持锁禁网络/磁盘 IO。
- 状态机与执行器分离：状态机是纯函数（可穷举合法/非法转移），执行器只在对象提交边界查询暂停/取消信号并驱动状态机。
- 凭据：`params_snapshot` 与 `migration_task_repos` 只存**引用名**；回源/发现时从运行时引用取值，取值不入任何持久化与日志（tracing 层加敏感字段过滤）。
- 离线包路径校验：新增服务配置 `migration-workdir`（离线包白名单根，默认不设=离线入口关闭）；Web 传入的路径先经 core 路径规范化（拒绝 `..`/绝对逃逸/空段/编码绕过），再判定规范化后是否真位于工作目录根内、目标存在且可读——校验为无 IO 可测的路径判定 + 一次 stat；服务端绝不据 Web 输入浏览或返回根外的目录内容（不做文件浏览器，无目录枚举接口）。
- 在线增量：首轮固化 `snapshot_time` 与对象清单指纹；最终扫描对比源现状与首轮清单，产出新增/修改/删除三类漂移列表。
- 三步工序：阶段 1 契约骨架（发现/计划/任务/进度/报告端点 utoipa）→ 阶段 2 向导对 devmock（迁移场景包）→ 阶段 3 后端实现（依赖三格式与 group 落地，本域最后做）。

## 5. 验收标准

对照 PRD §6.3（十二条）与 §4.3 完成定义，`testing-and-quality.md` §2「迁移状态机与幂等续传」「凭据处理」高风险区：

- **状态机穷举**（纯函数单元）：十态全部合法转移通过、非法转移（如 `succeeded→running`、`cancelled→paused`）一律拒绝；重启在途→interrupted。
- **发现一致性**：三类来源（离线原生数据目录 + REST/手动配置、在线 REST、自有包）发现结果与 Nexus 实际仓库列表/类型/成员顺序一致；裸 blob 明确降级；矩阵外来源被阻断或标实验性。
- **原生数据目录直读**：合成 Nexus 文件型 blob store fixture（含正常 blob、deleted 标记 blob、跨仓库共享内容），`.properties` 解析纯函数对样例全绿；直读归属出的 hosted 对象与源一致；deleted blob 被跳过；REST 拉取的配置与手动补的配置分别驱动 proxy/group 重建，二者结果一致（同一源两条配置路径等价）。
- **离线包路径校验**（安全，路径规范化高风险区）：手填路径经穷举恶意样本（`..` 回溯、绝对路径逃逸、软链接指向根外、空段、编码绕过）全部拒绝且不越出 `migration-workdir`；根外合法存在的目录也不可选（返回与「路径无效」一致的响应，不泄露根外是否存在）；`migration-workdir` 未配置时离线入口不可用。
- **快照一致性（离线）**：完整快照可导入；故意混入另一快照的清单或 blob → 整体摘要或对象校验阻断（详见 offline-package 规格）。
- **计划与冲突**：可选仓库/改目标名/映射凭据引用/预览冲突；默认禁覆盖，同校验跳过、不同校验未决前阻断执行；决策入快照与报告。
- **提交边界与中断**（故障注入）：大对象传输期触发暂停/取消/服务终止 → 无可见半成品索引；重启显示 interrupted、可一键续传；取消清理临时文件但不删已引用数据。
- **在线增量与切换**：源端制造新增/修改/删除 → 首轮后停写窗口最终扫描准确列出并处理全部漂移；删除项显式列出由管理员决定；仅零未处理漂移可全量成功。
- **hosted/proxy/group 全量校验**：hosted 源字节↔目标字节一致 + 协议元数据独立通过；proxy 每个正缓存对象被迁移/校验/或明确列未迁移（不抽样）；group 保序 + 三格式客户端语义验收（引用 m1-group §5）。
- **幂等重跑**：对未变化源二次执行迁移数为零、受支持对象全计校验一致跳过、无重复索引无孤儿 blob。
- **凭据零泄露**（强制自动断言）：任务参数快照、数据库、前端响应、日志、报告全量检索无明文 Nexus 凭据。
- **不支持项**：非三格式/系统数据入未迁移清单，整体结果不误标无损全成功。
- **持久化重启**：迁移完成后重启，历史/参数快照/进度/报告仍可查。
- **succeeded 严判**：构造「一个仓库被显式排除」「一个缓存对象不可迁移」「一个 proxy 凭据未映射」三种情形各自导致 partial 而非 succeeded，逐项计数正确。
- **原生数据目录全量（首选路径真机）**：从真实 Nexus 3.70.x 的磁盘 blob store 直读迁移 hosted 全量，配置分别经 REST 与手动补两条路径各验一次，结果与在线迁移一致；数百 GB 规模按 NFR-13 验收（磁盘直读不过网）。
- **真机维度（需用户确认）**：PRD §6.3 全十二条在真实 Nexus OSS 3.70.x 验收源上通过。

## 6. 风险 / 待定

- 真实 Nexus 3.70.x 验收源需用户准备（PRD §7.3 明列构成：三格式 × 三类型、每 group ≥2 成员且后序有独有版本、冲突/dist-tag 冲突/损坏/大文件/多页样本）——这是本域「真的能用」的唯一硬证据，无它不得标已交付。
- **Nexus 内嵌配置库直读已明确排除**（ADR-0015）：H2/OrientDB 为 JVM 私有格式、纯 Rust 无成熟方案；配置一律经 REST 或手动补。若某源既无法启动 Nexus 取 REST、管理员也无法提供配置，则该源只能裸 blob 尽力恢复，不得全量成功。
- **原生数据目录一致性**依赖迁移前停 Nexus 或文件系统快照（属操作约束）；直读运行中 Nexus 的活动 blob store 可能读到半写对象——文档须要求先停写/快照，工具对读取失败的对象按损坏类别报告不静默跳过。
- Nexus 3.70.x 的 blob store `.properties` 键名与布局需以真实实例核对（不同 blob store 类型/版本细节）；解析器对未知键容错、对缺关键键（如 repo-name）的 blob 入「不可识别」清单。
- Nexus REST 的组件分页在超大仓库上的稳定性（continuationToken 失效/重复）需真机压测；发现遍历必须容忍并去重（幂等键兜底）。
- 在线「最终增量扫描」依赖源端进入停写/只读窗口，属操作约束而非技术保证——文档须明确要求管理员操作，工具只校验窗口内零漂移。
- proxy 正缓存的「可枚举」边界：Nexus 侧能列出的正缓存才在范围；上游已删但 Nexus 仍缓存的对象照迁（以 Nexus 为源真相），不回源核验。
- 迁移落库经协议领域服务可能比直接搬运慢（多一层校验），但换来协议元数据不变量与幂等正确性——性能软目标见 NFR-14，超时不阻断但记录分析。
- 版本兼容：仅承诺 3.70.x；其他版本发现阶段阻断或标实验性，实验性来源不承诺全量成功（ADR-0007）。
