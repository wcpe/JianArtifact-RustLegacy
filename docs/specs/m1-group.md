# 功能规格：group 只读聚合仓库（M1-FR-012）

> 状态：已批准 / 开发中　·　关联 PRD：M1-FR-012（三格式 group 语义）、M1-FR-027（迁移后 group 目标语义的协议真源）　·　分支：main 直接提交，按域三步工序推进（ADR-0014）

## 1. 背景与目标

属 M1，安全性最敏感的一块：group 是按固定成员顺序聚合多个同格式成员仓库的**只读虚拟仓库**。核心难点不是聚合本身，而是**逐成员 ACL 过滤下的零泄露**——调用方对 group 有 read 不代表对每个成员都有 read，任何响应都不得暴露无权成员的存在或其内容。本规格建立在 `m1-repository-core.md`（授权纯函数、三格式协议）之上，是 `testing-and-quality.md` §2「group 聚合零泄露」高风险区的落地。三格式协议语义分别引用 raw/maven/npm 规格，不重复。

## 2. 需求（要什么）

**通用：group 模型与访问门**

- group 属性：有序成员列表（`repository_group_members`：group_id、member_id、position，member 必须与 group 同 format、且只能是 hosted/proxy——不支持 group 嵌套 group，M1 范围）。
- 两道权限门，顺序不可颠倒：
  1. **group read 门**：调用方对 group 本身无 read → 按仓库核心的零存在性泄露规则返回 404（与不存在一致）。
  2. **逐成员 read 过滤**：通过门 1 后，**只对调用方有 read 权限的成员**执行查找/聚合；无权成员从本次请求中完全剔除，如同不存在。
- 写操作（任何格式的 PUT/DELETE/publish）→ 405（group 只读，PRD 明确不支持写 group）。
- 成员为 proxy 时，聚合触发的回源与缓存落在**该成员仓库**（group 不持有 blob，只做转发与合并）；单飞、错误分类继承成员仓库机理。
- 可读成员返回 404 时继续尝试后续可读成员；可读成员发生超时、5xx、传输损坏或本地损坏时立即返回稳定失败，不得把真实故障伪装成未命中。无权成员完全不访问，因此其故障不影响结果，也不得记录到调用方可见响应。

**FR-012 三格式聚合语义**

- **Raw group（按序命中）**：按成员顺序在**可读成员**中查找路径，命中即返回、后续成员不再查（first-match）；全部可读成员未命中 → 404。无权成员在顺序中被跳过，不影响命中结果、不泄露其存在。
- **Maven group（metadata 聚合 + 构件按序命中）**：
  - 构件/sidecar 请求：按序在可读成员中 first-match（同 Raw）。
  - artifact 级 `maven-metadata.xml`：**只聚合可读成员**的版本集合，合成统一 metadata（versions 并集、latest/release 按聚合后版本重算、lastUpdated 取最大）；无权成员的版本一律不出现。
  - SNAPSHOT 版本目录的 `maven-metadata.xml` 及其 sidecar 不聚合，按可读成员顺序 first-match，避免把不同成员的 timestamp/buildNumber 拼成无效快照。
  - 版本冲突（同坐标同版本存在于多个成员）：按成员顺序，**前序成员优先**提供构件本体；metadata 层面为版本并集（同版本只列一次）。
- **npm group（packument 合并 + tarball 按序）**：
  - packument：**只合并可读成员**的 packument——`versions` 为可读成员版本并集，`dist-tags` 按成员顺序合并（**前序成员的 tag 优先**，如 latest 冲突取前序），`time` 取提供该版本的前序成员；无权成员版本与 dist-tag 一律不出现。每个版本的 `dist.tarball` 必须重写为**当前 group 自身**的绝对地址，不暴露成员仓库名或上游地址。
  - tarball：group 根据已选中的前序版本提供者在服务端路由到对应可读成员，客户端始终请求 group 地址。
  - 版本冲突：同 version 由前序成员优先提供；dist-tag 冲突前序优先。

**零泄露不变量（贯穿三格式）**

无权成员的**名称、坐标、版本号、dist-tag、数量、以及"因无权而被跳过"这一事实**都不得出现在任何响应体、响应头、错误消息或状态码差异中。对调用方而言，可读子集聚合出的结果必须与「group 只由这些可读成员组成」在观察上完全一致。

## 3. 设计（怎么做）

- 模块落点：`repository/group`（成员解析 + 逐成员 ACL 过滤，产出「本次请求的可读成员有序列表」）→ 交由各 `protocol/{格式}` 的聚合器（纯函数：可读成员的元数据集合 → 合成结果）。协议层经领域服务取成员数据，禁直连数据库（ADR-0006）。
- 聚合器为无 IO 纯函数（版本并集、dist-tag 合并、metadata 合成、first-match 选择），输入是「已按 ACL 过滤的成员元数据列表」，便于穷举测试；ACL 过滤在其上游一次性完成，聚合器内不再见到无权成员。
- 复用：Maven metadata 合成、npm packument 合成的单仓库纯函数（maven/npm 规格）扩展为「多成员输入」版本，或组合调用——实现时择一，避免两套版本排序逻辑。
- 数据：不为 group 增制品表（group 不持 blob）；`repository_group_members` 见核心规格数据模型。
- N+1 防护：一次 group 请求对成员的元数据读取批量进行，禁止循环内逐成员查库（架构不变量）。
- 三步工序：阶段 1 契约骨架（group 经同一格式端点，无独立端点，契约随格式端点）→ 阶段 2 前端仓库详情展示 group 成员顺序 → 阶段 3 后端实现（依赖三格式与授权纯函数落地）。

## 5. 验收标准

对照 PRD §7.2（三格式 group + group ACL 组合）与 `testing-and-quality.md` §2「group 聚合零泄露」，全部穷举：

- **三类 ACL 场景穷举**（每格式）：①可读 group + 部分成员可读、②可读 group + 全部成员不可读、③不可读 group——
  - 场景①：结果只含可读成员内容；无权成员的名称/坐标/版本/dist-tag/数量/错误原因零泄露；响应与「group 仅由可读成员组成」逐字节一致。
  - 场景②：表现为「空 group」——Raw 404、Maven 空 metadata、npm 空/最小 packument；不得泄露存在不可读成员。
  - 场景③：按核心零存在性泄露返回 404（与 group 不存在一致）。
- **成员顺序语义**：后序成员放置前序没有的版本/路径 → 可读时可命中下载；前序后序同版本冲突 → 前序优先提供本体（PRD §7.2 明列，Maven/npm 各验）；Maven SNAPSHOT 版本 metadata/sidecar 同样 first-match。
- **成员故障语义**：可读成员 404 继续后序；可读成员超时/5xx/传输损坏返回稳定错误且不继续掩盖故障；同一请求中无权成员不得被访问。
- **metadata/packument 只聚合可读成员**：构造「可读成员 A + 不可读成员 B，B 有独有版本」，断言响应无 B 的任何版本痕迹；对比调用方有权时该版本出现，证明差异仅由 ACL 决定且无侧信道（数量、耗时不作为泄露面，但响应内容必须一致）。
- **写入拒绝**：三格式对 group 的写操作均 405。
- **proxy 成员**：group 触发的未命中回源缓存落在成员仓库、单飞合并生效（复用 core NFR-08 口径按 group 路径抽查）。
- **真机维度（需用户确认，隔离环境官方客户端）**：PRD §7.2 全部 group 客户端验收——Raw group 按可读成员顺序命中、Maven group 后序可读成员独有版本可 `mvn` 下载且冲突按优先级、npm group 后序可读成员独有版本可 `npm install` 且 dist-tag/tarball 地址改写符合规则。
- 迁移后 group（FR-027）以本规格为协议验收真源：迁移重建的 group 保成员顺序，客户端按本规格语义读取成功。

## 6. 风险 / 待定

- **不支持 group 嵌套 group**（成员只能是 hosted/proxy）：Nexus 允许 group 套 group，迁移遇到时按「不支持项」处理（FR-033），报告列出、不静默展开；如需支持按新需求登记。
- **dist-tag / Maven latest 冲突的"前序优先"** 为本规格选定规则（对齐直觉：成员列表靠前的更权威）；与某些 Nexus 配置的合并策略可能不同，迁移验收若暴露差异，记录并评审是否需可配置（当前不预留配置项）。
- 零泄露要求响应对可读子集「逐字节一致」，意味着错误消息也不能因「跳过了无权成员」而措辞不同——实现时统一错误文案，避免无意侧信道。
- 数量与耗时侧信道：本规格不把响应时间纳入零泄露断言（时序攻击超出 M1 威胁模型），但响应内容层面的数量泄露（如"共 N 个成员"）严格禁止。
