# 功能规格：仓库核心——可见性、ACL、仓库管理与 hosted/proxy 通用能力（M1-FR-007~011、019~021）

> 状态：草拟　·　关联 PRD：M1-FR-007~011、019、020、021　·　分支：main 直接提交，按域三步工序推进（ADR-0014）

## 1. 背景与目标

属 M1，仓库域核心：定义授权判定、仓库生命周期与 hosted/proxy 两类仓库的格式无关通用机理，是三个格式规格（raw/maven/npm）与 group 规格的共同地基。决策依据 ADR-0002（存储模型）、ADR-0004（授权模型）、ADR-0005（仓库类型）、ADR-0006（协议适配边界）。依赖 `m1-auth.md` 的鉴权提取器与服务基座。

## 2. 需求（要什么）

**FR-007 可见性 + FR-008 ACL（授权判定）**

- 授权判定为**无 IO 纯函数**：`authorize(访问者, 仓库状态, ACL 条目, 动作) → 允许 | 拒绝原因`，调用方负责装配输入；全部权限决策必须经此函数，前端隐藏入口不是安全边界。
- 动作三级且**向下包含**：admin ⊃ write ⊃ read。read=下载/浏览/元数据；write=上传/发布/覆盖/删除制品；admin=仓库配置编辑、可见性与 ACL 管理、停用与删除。
- 身份 × 权限矩阵：全局 Admin 对所有仓库拥有 admin；普通用户按仓库 ACL 条目（用户级授予 read/write/admin 之一）；匿名仅对 public 仓库拥有 read。
- **零存在性泄露**：对无 read 权限的 private 仓库，任何请求（管理 API 与格式端点、任意方法与路径）返回与「仓库不存在」完全一致的 404 响应体；仓库列表与搜索结果只含调用方可读仓库，无数量侧信道。
- **停用仓库**：格式端点一律按 404 处理（不区分停用与不存在）；管理端对有权限者可见「已停用」状态并可重新启用。

**FR-009 仓库管理**

- 创建（Admin）：name（全局唯一，字符集 `[a-z0-9-]`，1–64 字符）、format（raw/maven/npm）、type（hosted/proxy/group）、visibility、类型专属配置（proxy 上游、group 成员——成员语义见 `m1-group.md`）。**format 与 type 创建后不可变**。
- 编辑（仓库 admin）：可见性、覆盖策略、proxy 上游与凭据引用、停用/启用。
- 删除（仓库 admin，高风险动作，必须显式二段确认——请求带确认参数复述仓库名）：
  - `mode=config`：删除仓库配置、ACL 与制品索引，不触碰 blob 本体；响应报告因此失去全部引用的 blob 数量（遗留物理回收给 M3 GC，见 §6）。
  - `mode=data`：在 config 基础上，物理删除**无其他引用**的 blob（内容寻址跨仓库共享，引用检查防误删）。

**FR-010 hosted 通用能力（格式无关机理，供各格式协议层复用）**

- 上传：全程流式（缓冲上限 NFR-02/03），拒绝超过 NFR-01（5 GiB）的对象；写入严格走「临时文件边写边算摘要 → 校验 → 落定内容寻址路径 → 提交索引」四步与提交守卫（ADR-0002），单遍流式同时计算 sha256/sha1/md5（Maven sidecar 需要后两者）。
- 磁盘保护：写入前按 NFR-11 阈值检查，不足返回存储不足错误（507 语义）。
- 下载：流式返回，携带校验和头；不支持 Range 断点续传（范围外，原生客户端不依赖）。
- 删除：按路径删除索引，无其他引用的 blob 物理回收（与写路径同守卫纪律，不留半删状态）。
- 覆盖策略：仓库级配置 `allow | deny`（deny 时同路径再上传返回冲突错误）；Maven release/snapshot 细化语义由 `m1-maven.md` 在此开关之上定义。
- 路径安全：所有客户端路径经统一规范化（拒绝 `..` 回溯、绝对路径、空段、控制字符与编码绕过），越界一律拒绝。

**FR-011 proxy 通用能力**

- 上游配置：URL + 可选**凭据引用**（只存引用名，运行时从环境变量取值——与迁移域 FR-039 同一机制）；凭据不落库、不进日志。
- 缓存未命中：**单飞合并**——同仓库同路径并发未命中只发起一次上游拉取（NFR-08 以 32 并发验收）；首个请求者边回源边流式转发并写临时文件，完成后按四步提交为正缓存；其余等待者在提交后从本地流式读取。
- 缓存命中直接本地流式返回；不实现负缓存（对「不存在」结果不缓存，见 PRD 术语表）。
- 上游错误分类传播且不污染缓存：不存在（404）、连接/超时、上游 4xx、上游 5xx、传输中断流——各成稳定错误类别，等待者收到同类错误。
- 上游超时钉死（配置项）：连接 10 秒、响应首字节 30 秒、传输空闲 60 秒；不做自动重试（客户端自理）。

**FR-019 仓库与制品浏览（管理 API）**

- 仓库列表：按权限过滤（见零泄露），分页（NFR-16），含格式/类型/可见性/停用状态。
- 仓库内浏览：目录层级列表与文件详情（大小、各校验和、更新时间），分页。
- 搜索：仓库内路径子串匹配，分页；跨仓库全局搜索为 M2 能力，范围外。

**FR-020 使用方式片段**

- `GET /api/v1/repos/{name}/usage`：后端按格式生成结构化片段（raw：curl 上传/下载；maven：settings.xml 与 distributionManagement；npm：registry 配置与 publish），URL 由服务端拼装保证单一真源；凭据一律以 `<令牌>` 占位符出现，不嵌任何真实 Token。

**FR-021 健康检查与就绪自检**

- 语义已钉死于 `API.md` §5：`/healthz` 纯存活；`/readyz` 在线探测元数据库（读写探测）与 blob 数据目录（写删探针文件），任一失败 503，明细只落中文日志。
- 本端点落地即触发 `m1-build-deploy.md` §5 的 FR-043 真机验收补验。

## 3. 设计（怎么做）

- 模块落点：`domain/authorize`（纯函数）、`repository`（仓库生命周期与浏览服务）、`storage`（BlobStore：内容寻址 sha256 前两位分桶 + 提交守卫 + 引用检查回收）、`protocol` 侧只经领域服务调用（ADR-0006）；`api` 层 handler + utoipa。
- 数据表草案（权威以迁移脚本为准）：`repositories`（id、name 唯一、format、type、visibility、disabled、overwrite_policy、proxy_upstream_url、proxy_credential_ref、created_at）、`repo_acl`（repo_id、user_id、permission，联合唯一）、`artifacts`（id、repo_id、path，联合唯一、blob_sha256、size、sha1、md5、cached 标记（proxy 正缓存）、created_at、updated_at）。blob 引用计数由 `artifacts.blob_sha256` 聚合查询承担，不设独立计数表。
- 单飞实现约束：持锁期间禁网络/磁盘 IO（架构不变量）——单飞注册表仅在锁内做等待者登记/摘除，回源与落盘全部在锁外执行。
- 端点空间：管理 API `/api/v1/repos*`；格式端点 `/repository/{仓库名}/...` 的通用鉴权与路径规范化在本域落地，具体协议行为归各格式规格。
- 三步工序（ADR-0014）：阶段 1 契约骨架（repos CRUD/浏览/usage/healthz/readyz 的 utoipa 契约）→ 阶段 2 前端对 mock（仓库列表/详情/文件浏览页与使用片段展示）→ 阶段 3 后端实现（依赖 m1-auth 落地）。

## 5. 验收标准

对照 PRD §6.1 与 `testing-and-quality.md` §2 高风险区：

- **授权矩阵穷举**（纯函数单元测试 + 端点集成抽查）：{匿名、普通用户无 ACL、ACL read/write/admin、全局 Admin、被禁用用户} × {public、private} × {read、write、admin} × {正常、停用仓库} 全组合与预期一致；动作包含关系（admin⊃write⊃read）成立。
- **零存在性泄露**：无权 private 与不存在仓库的响应（状态码、错误体、头集合）逐字节一致；仓库列表/搜索在无权时不出现名称与计数痕迹。
- **blob 提交顺序与守卫**（故障注入）：上传/回源过程分别注入进程终止、磁盘不足、DB 提交失败、客户端断流——不留可见半成品索引，临时文件可识别可回收且不被读取路径命中；同内容并发上传不产生重复 blob。
- **路径规范化**：恶意样本集（`../` 回溯、URL 编码绕过、绝对路径、空段、超长路径）全部拒绝且不越出仓库根。
- **单飞合并**：NFR-08 的 32 并发同路径未命中，上游侧计数恰为 1；上游 404/超时/5xx/断流四类场景等待者收到对应类别错误且缓存无污染残留。
- **删除语义**：mode=config 后索引消失、blob 留存且数量入响应；mode=data 后无引用 blob 物理消失、被其他仓库引用的 blob 保留；缺确认参数的删除请求被拒。
- **磁盘阈值**：模拟低空间触发 507 且不留半成品（对齐 NFR-11）。
- **readyz 真实性**：破坏数据库文件/置 blob 目录只读 → 503 且明细仅在日志；恢复后 200。
- **大文件与内存**（对齐 NFR-01/02/06）：5 GiB 样本上传/下载/回源的 RSS 增量与峰值达标，输出 cgroup 证据。
- **真机维度**（需用户确认）：部署实例上 curl 完成 public/private 仓库的可见性与 ACL 行为抽查；`/readyz` 探活接入 FR-043 自动回滚补验。

## 6. 风险 / 待定

- **mode=config 删除的遗留 blob**：M1 无 GC（M3 能力），仅删配置会留下无引用 blob 占盘——响应中报告数量、文档明示；若评审认为不可接受，可改为仅提供 mode=data（评审点）。
- 上游超时三值（10/30/60 秒）与仓库名字符集为本规格选定约定，开发前可调。
- 单飞等待者在首请求者失败后的行为定为「收到同类错误、不自动接力重试」——接力回源会放大上游故障，如需要按新需求登记。
- proxy 凭据引用机制与迁移域共用，其引用格式（环境变量名约束）在本域实现时定稿并回填 `m1-nexus-migration.md`。
