# 功能规格：M1 非功能需求数值（NFR）

> 状态：已定稿（规模参数经用户确认于 2026-07-12）　·　关联 PRD：§5.5 待钉死数值清单、§6.4 性能与可靠性验收　·　分支：不涉及（约束文档，随各功能分支引用）

## 1. 背景与目标

PRD §5.5 规定：大文件、缓冲、并发、内存、磁盘与迁移规模的验收数值必须在实现前钉死，缺数值不得开始相关实现。本规格是这些数值的**唯一权威定义**；PRD §5.5 仅保留摘要表。所有涉及流式处理、并发与迁移的实现和测试，以本文数值为准。

数值推导依据（用户确认的规模参数）：目标部署机 4 核 8 GiB 内存的单机 Linux 服务器；必须支持的最大单制品 5 GiB；客户端并发规模 ≤ 50；Nexus 迁移存量验收目标约 10 万对象 / 100 GiB。

## 2. 钉死数值总表

| 编号 | 项 | 数值 | 形态 |
|---|---|---|---|
| NFR-01 | 最大单制品大小 | 5 GiB（超限上传拒绝，返回明确错误） | 配置项，默认 5 GiB |
| NFR-02 | 流式缓冲块大小 | 8 MiB（上传、下载、代理回源、迁移搬运共用；缓冲占用不随对象大小增长） | 固定常量 |
| NFR-03 | 最大单请求内存缓冲 | 16 MiB（含协议解析开销；唯一例外见 NFR-04） | 固定常量 |
| NFR-04 | npm publish 请求体上限 | 128 MiB（npm 协议的 publish 体为内嵌 base64 附件的 JSON，必须整体解析，是唯一允许整体驻留内存的请求类型，计入 NFR-06 峰值） | 配置项，默认 128 MiB |
| NFR-05 | 常驻内存（空闲稳态） | ≤ 256 MiB RSS | 验收目标 |
| NFR-06 | 负载峰值内存 | 验收负载（NFR-07）与 5 GiB 大文件传输期间，进程 RSS ≤ 1 GiB；单个大文件传输引起的 RSS 增量 ≤ 256 MiB | 验收目标 |
| NFR-07 | 验收并发负载 | 50 并发混合读写持续稳定（M1 不实现应用层限流与并发限制，那是 M4 能力；本项是验收负载而非运行时开关） | 验收目标 |
| NFR-08 | proxy 单飞验收并发数 | 32 并发同仓库同路径缓存未命中 → 恰好一次有效上游拉取 | 验收参数 |
| NFR-09 | 迁移任务内对象并发 | 默认 4，上限 8（有限并发，不挤占正常流量） | 配置项 |
| NFR-10 | 迁移期间正常请求可用性 | 迁移满速运行时，1 MiB 制品下载在本地网络 P95 ≤ 1 s | 验收目标 |
| NFR-11 | 磁盘最低保留空间 | 剩余 < 5 GiB 或 < 总容量 5%（二者取先触发者）：拒绝新上传与代理落盘（返回存储不足错误），迁移停止接收新对象、当前原子对象完成后进入可恢复失败态 | 配置项，默认 5 GiB / 5% |
| NFR-12 | 迁移目标空间估算系数 | 迁移计划要求目标可用空间 ≥ 源估算字节 × 1.1 + NFR-11 保留量，不满足时计划给出明确警示 | 固定常量 |
| NFR-13 | 迁移验收数据规模 | ≥ 100,000 对象、≥ 100 GiB 总字节；组成须满足 PRD §6.3 的样本要求，且含 ≥ 1 个 5 GiB 对象、资产清单跨 > 2 个完整分页 | 验收目标 |
| NFR-14 | 迁移完成时限（软目标） | 验收环境本地网络下，NFR-13 规模的在线全量迁移 ≤ 4 小时；超时不阻断验收但必须记录并分析 | 软目标 |
| NFR-15 | 幂等重跑时限 | 对已一致的 NFR-13 规模源二次执行，全部对象精确计为跳过，耗时 ≤ 30 分钟 | 验收目标 |
| NFR-16 | 列表分页 | 默认页大小 50，最大 200；所有列表与发现接口强制分页 | 固定常量 |

## 3. 设计（数值如何落地）

- NFR-01/04/09/11 为服务端 TOML 配置项（命名与注释遵循 `.claude/rules/config-files.md`），其余为代码常量或纯验收目标，不为验收目标增加运行时开关（防镀金）。
- 上游超时、重试等 proxy 行为数值不属于本规格，由 `m1-repository-core.md`（FR-011）与各协议规格定义。
- 本规格不引入任何限流、配额、GC 能力（分属 M3/M4，见 `.claude/rules/scope-discipline.md`）。

## 5. 验收标准（证据要求）

每项数值的验收都必须产出客观证据，测试与验收报告引用 NFR 编号：

- **NFR-02/03/06（缓冲与峰值内存）**：上传、下载、代理回源、迁移搬运各以 5 GiB 样本执行，采集容器 cgroup 内存峰值（`memory.peak`）或等价 RSS 采样序列，证明增量 ≤ 256 MiB、全程 ≤ 1 GiB，且缓冲不随对象大小线性增长（对比 1 GiB 与 5 GiB 样本的峰值差异）。
- **NFR-01/04**：超限上传与超限 publish 返回明确的中文错误且不产生半成品索引与孤儿 blob。
- **NFR-05**：服务空载运行 10 分钟后的 RSS 采样 ≤ 256 MiB。
- **NFR-07/10**：50 并发混合读写压测期间无错误响应放大；迁移满速时 1 MiB 下载 P95 ≤ 1 s，输出延迟分布。
- **NFR-08**：32 并发同路径未命中，上游侧计数恰为 1（对齐 PRD §6.2、§8 高风险区）。
- **NFR-11/12**：以填充磁盘或挂载小容量卷方式触发阈值，验证拒绝写入与迁移可恢复失败态；迁移计划输出空间估算与警示。
- **NFR-13/14/15**：真实 Nexus OSS 3.70.x 验收源达到规模要求；迁移报告输出对象数、字节数与耗时；二次执行输出全量跳过计数与耗时。
- 以上涉及真实环境的项（NFR-06/07/10/13/14/15）为实机验收，需用户确认通过；单元与集成测试全绿不替代。

## 6. 风险 / 待定

- 4C8G 上 SQLite 与 blob 同盘时，100 GiB 迁移的磁盘 IO 可能成为 NFR-14 软目标的瓶颈——首次实机验收后如超时，分析结论回填本节。
- npm 生态存在超过 128 MiB 的极端大包；如实际使用中遇到，调大 NFR-04 配置即可，不需改架构。
- 若未来部署机规格显著变化（如降级到 2C4G），本规格数值须整体复核后出新版本，不做单点悄改。
