# 接口契约：JianArtifact

> 对外接口约定的单一真源说明。本文档在初始化阶段只登记「约定与稳定契约」，不虚构未实现端点；约定变更必须原地更新本文档并通过文档漂移门禁。

## 1. 契约真源

- 服务端 HTTP 端点、参数与数据模型定义，以后端代码经 utoipa 生成的 OpenAPI 文档为**唯一真源**（见 ADR-0012）；其中包含管理 API、健康探针与格式协议路径。
- OpenAPI 契约的两个获取途径：运行中服务的 `GET /api/v1/openapi.json`；或不启动服务执行 `jianartifact openapi` 将契约 JSON 打印到标准输出（供前端类型生成与 devmock 契约比对在构建期消费）。
- 前端 TypeScript 类型由该 OpenAPI 自动生成；devmock 的双向契约测试只覆盖 `/api/v1` 管理业务路径，健康探针与 `/repository` 格式协议由各自测试验证，任何管理契约漂移即质量门禁失败（见 ADR-0010）。
- 本文档只记录跨端点的通用约定；当出现新的跨端点约定（新的错误码域前缀、新的路径空间等）时同步更新本文档。

## 2. 通用约定

### 2.1 路径空间划分

- 管理 API 统一前缀：`/api/v1`，请求与响应均为 UTF-8 编码的 JSON。`v1` 内保持向后兼容；破坏性变更必须升级版本前缀并另行评审。
- 格式协议端点与管理 API 完全分离；规划统一挂载于 `/repository/{仓库名}/` 之下，并随对应格式域落地：
  - Raw：按任意规范化路径直接读写，路径必须经过规范化与越界防护。
  - Maven：Maven2 标准仓库布局（POM、构件、metadata、checksum sidecar）。
  - npm：npm registry 协议布局（packument、tarball、dist-tag、scoped package）。
- 格式协议通用路径的 GET/HEAD/PUT/DELETE 与仓库根目录 GET 已纳入同一 OpenAPI 并真实挂载；Raw hosted/proxy 已落地真实 HTTP 语义，Maven、npm 与 group 仍按路线图逐域替换占位。包管理器与自动化客户端只依赖该路径空间，无需理解管理 API。
- 首启管理员设置页固定为 `/setup`，一次性令牌只放在 URL fragment（`/setup#token=<令牌>`）；fragment 不属于 HTTP 请求路径，服务端不得从 query 或路径接收令牌。页面调用 `/api/v1/setup/*` 完成状态查询与提交。
- 健康检查端点独立于上述两个路径空间（见 §5）。

### 2.2 鉴权

- 管理 API：`Authorization: Bearer` 携带 JWT 会话令牌或 API Token（见 ADR-0003）；`GET /api/v1/auth/me` 返回当前权威用户身份与角色，前端不得按用户名推断角色。
- 格式协议支持 `Authorization: Basic`（用户名 + 密码，或用户名 + API Token）与 Bearer；每次请求都复核用户启用状态与凭据有效性。
- 匿名请求仅允许读取 public 仓库；private 无 read、仓库不存在与停用仓库在协议面统一返回 404，已有 read 但无 write 返回 403（见 ADR-0004）。
- 携带凭据但校验失败的请求必须以 401 拒绝，**不得**降级为匿名身份或任何其他已认证身份继续处理。
- JWT 会话同时校验签名、到期时间、会话撤销哈希、用户启用状态与用户会话版本；同一旧会话并发刷新仅允许一个请求换发成功。
- 会话退出、Token 吊销、用户禁用或口令修改提交成功后，下一次使用对应既有凭据的请求必定失败。

### 2.3 首启管理员初始化

- `GET /api/v1/setup/status` 无需鉴权，固定返回 200 与 JSON `{"setup_required": true|false}`。只有用户表为空且一次性设置入口有效时为 `true`；响应不得包含令牌、令牌文件路径、数据库路径或环境变量状态。
- `POST /api/v1/setup` 无需既有账号鉴权，请求 JSON 为 `token`、`username`、`password` 三个字符串字段。用户名去除首尾空白后必须非空；口令按 Unicode 字符数而非 UTF-8 字节数计至少 12 个字符。有效令牌成功创建首个 Admin 时返回 204 且无响应体。
- 令牌来自数据库同目录权限为 `0600` 的 `initial-admin.token`，内容为 32 字节密码学安全随机数的 64 位小写十六进制表示。浏览器从 `/setup#token=<令牌>` 的 fragment 读取后仅在 POST 请求体提交；不得把令牌写入 query、路径、响应、日志或数据库。
- 首个用户创建使用数据库原子条件保护；多个有效并发请求只能一个返回 204，其余统一返回 404 / `SETUP_UNAVAILABLE`。创建成功后用户表非空是永久关闭依据，并删除令牌文件；不得通过重启、重新放置令牌文件或配置开关重新开放。
- 稳定错误：请求体为空、JSON 损坏或 `Content-Type` 不是 JSON 时返回 400 / `SETUP_REQUEST_INVALID`；用户名为空返回 400 / `SETUP_USERNAME_REQUIRED`；口令不足 12 个 Unicode 字符返回 400 / `SETUP_PASSWORD_TOO_SHORT`；令牌无效、入口已关闭、令牌重复使用或并发请求被其他请求抢先完成时，均统一返回 404 / `SETUP_UNAVAILABLE`。错误响应沿用 §3 统一结构，不回显敏感输入，也不得让调用方区分具体不可用原因。

### 2.4 敏感数据

- API Token 明文只在签发响应中出现一次；此后任何接口只返回其元数据（名称、创建时间、过期时间等），持久化只存哈希。
- 外部系统凭据（迁移用 Nexus 凭据、proxy 上游凭据等）在所有请求、响应、持久化与报告中一律以安全运行时引用表示，任何接口不得返回明文。
- 「使用方式片段」等生成内容不得内嵌真实 Token，只允许占位提示用户自行填入。
- 任何响应与错误消息不得包含密码、令牌明文、内部文件路径或内部拓扑信息。

### 2.5 仓库管理契约

- 仓库列表、详情、创建、PATCH、删除、ACL、目录浏览与路径搜索端点已由真实 Rust 领域服务和 SQLite 持久化承载；使用片段仍按路线图后续落地。
- ACL 设置与移除以精确用户名作为路径键：`/api/v1/repos/{name}/acl/{username}`；客户端必须对用户名做路径编码，不得依赖数据库用户 ID。仓库 admin 可直接按用户名授权，不依赖全局用户列表权限。
- 仓库 PATCH 中字段缺失表示不更新；`upstream_credential_ref: null` 表示清空上游凭据引用，其他类型专属必填字段不接受 null 清空。
- 浏览与搜索响应的 `FileEntry.path` 是仓库根相对完整路径，客户端以该字段为准，不自行拼接父目录与条目名。
- 类型专属配置：hosted 使用覆盖策略，Maven hosted 另有版本策略，proxy 使用上游 URL 与可选凭据引用，group 使用有序成员列表；group 响应只返回调用方可读成员，未提交 `members` 的普通 PATCH 不得据此覆盖完整成员关系。
- 私有仓库无 read 权与仓库不存在统一返回 `REPO_NOT_FOUND` / `仓库不存在或无权访问`，列表与详情均不得泄露名称或数量；已有 read 但动作权限不足时返回 403。group 成员配置中，不存在与调用方不可读的候选统一返回 `REPO_INVALID_CONFIG` / `group 成员不存在或无权访问`。
- 删除先校验仓库 admin 权限，再校验确认头与删除模式，避免无权调用方利用确认参数探测仓库存在性；`mode=config` 删除配置与索引、保留无引用 blob 并报告 `orphaned_blobs`，`mode=data` 仅物理回收无其他仓库引用的 blob 并报告 `reclaimed_blobs`。

### 2.6 Raw hosted/proxy 协议

- hosted `PUT` 流式写入并按覆盖策略返回 201/200/409；`GET` 流式下载，`HEAD` 返回同组元数据头且无响应体，`DELETE` 返回 204/404。对象响应固定携带 `Content-Length`、按扩展名推断的 `Content-Type`、强 `ETag`，以及 `X-Checksum-Sha256`、`X-Checksum-Sha1`、`X-Checksum-Sha512`、`X-Checksum-Md5`。
- hosted 目录以尾随 `/` 表示，仓库根 `/repository/{name}/` 返回 JSON 分页索引；对象路径不得为空或尾随 `/`，规范化后 UTF-8 长度上限为 4096 字节。hosted query 不参与路径键。
- proxy 仅允许 GET/HEAD；缓存未命中按仓库、路径与 `upstream_url` 配置快照单飞回源，完整流式落盘并提交正缓存后才从本地 blob 响应，首次 HEAD 同样完整缓存。任意 query 返回 400，写操作返回 405。
- proxy 缓存事务仅在仓库仍为 proxy 且当前 `upstream_url` 等于回源预期快照时提交索引；旧配置提交被拒后，请求重新读取仓库与授权状态，并按新配置最多透明重试一次。若重试期间配置再次变化，则返回稳定 503，表示代理配置连续变化且本次请求未写入旧缓存。
- proxy 禁止自动重定向，3xx/其他 4xx/5xx/断流分别以稳定 `PROXY_UPSTREAM_*` 类别返回 502；上游 404 返回 404，连接或响应超时返回 504。失败不写入缓存索引。
- proxy 凭据引用只存环境变量名；运行时变量值必须是完整的 `Basic …` 或 `Bearer …`，只注入 `Authorization` 头，明文不得进入数据库、响应或日志。修改 `upstream_url` 会在同一数据库事务内失效该仓库全部正缓存索引并登记 blob 回收意图，单独修改凭据引用保留缓存。

## 3. 错误约定

管理 API 所有非 2xx 响应使用统一错误结构；请求关联 ID 统一放在 `X-Request-ID` 响应头中：

```json
{
  "code": "REPO_NOT_FOUND",
  "message": "仓库不存在或无权访问"
}
```

- `code`：稳定错误码，全大写下划线命名，按域划分前缀（如 `AUTH_`、`REPO_`、`MIGRATION_`）；错误码一经发布不得更改语义，客户端只依赖 `code` 做分支。
- `message`：面向人的中文消息，措辞允许演进，客户端不得据此做逻辑分支。
- `X-Request-ID`：请求关联 ID，与服务端日志一一对应，用于问题定位；客户端可在报障时一并提供。

不泄露原则：

- 对无权限的私有资源，返回与「资源不存在」完全一致的状态码与错误码，不泄露存在性；列表、搜索与计数结果同样不得包含私有资源的名称、坐标或数量侧信道。
- 错误消息不得包含内部路径、SQL、堆栈或上游凭据。
- 格式协议端点的错误以各协议的 HTTP 状态码惯例为准，同样遵守以上不泄露原则。

## 4. 分页约定

- 所有列表类接口**必须分页**，不提供全量返回模式。
- 请求参数：`page`（从 1 开始）、`page_size`（存在服务端上限，超出上限时按上限值执行）。
- 名称筛选（可选）：仓库 / 用户 / Token 列表接受可选 `q` 参数，按名称（仓库名 / 用户名 / Token 名）子串大小写不敏感筛选后再分页；`total` 反映筛选后的数量。
- 响应结构：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

- 遍历保证：列表使用稳定排序，翻页无重复、无遗漏；验收数据量至少覆盖两个以上完整页。

## 5. 健康检查约定

- 健康（liveness）：`GET /healthz`，进程存活即返回 200，不做依赖探测。
- 就绪自检（readiness）：`GET /readyz`，对关键依赖做在线探测——元数据库可读写、blob 数据目录可写——全部通过返回 200，任一失败返回 503；失败明细只记录到服务端中文日志，响应体不携带。
- 两个端点均无需鉴权；响应只包含粗粒度状态，不泄露内部路径、拓扑、依赖细节或精确版本信息。
- `/readyz` 同时是部署脚本探活与自动回滚（M1-FR-043，见 `specs/m1-build-deploy.md`）的判定接口：部署侧仅依据状态码判定，200 视为健康。

## 6. 端点 / 方法

具体业务端点与方法由 utoipa 生成的 OpenAPI 呈现明细（§1），本文不手抄完整清单；本节仅在形成新的跨端点稳定契约时补充说明。当前 `/repository/{name}/` 与 `/repository/{name}/{path}` 已登记并实现 Raw 所需方法，其他格式按对应规格继续落地。
