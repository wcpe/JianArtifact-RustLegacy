# ADR-0013：单二进制交付

## 状态
已接受

## 背景
第一期运行形态的硬要求是：React 静态产物由 Rust 服务提供，部署时不需要独立前端服务或 Node 运行时。需求将「是否继续追求单一可执行文件内嵌前端」留待本 ADR 决定。产品定位为低运维自托管，部署与升级的复杂度直接影响采用意愿。

## 决策
- 前端构建产物（dist）通过 **rust-embed 在编译期内嵌**进后端二进制，正式交付物为**单个可执行文件**（加数据目录即可运行）。
- 构建顺序硬约束：**先前端、后后端**——后端编译前必须已存在当次的前端产物，构建脚本与 CI 流水线必须显式保证该顺序，禁止使用陈旧产物。
- 开发态使用 Vite dev server 与后端联调，不走内嵌路径；内嵌仅用于正式构建。

## 理由
- 单文件交付把部署降为「复制一个文件 + 准备一个数据目录」，升级即替换文件重启，符合低运维定位，且沿用已验证的设计。
- 编译期内嵌使每个版本的二进制自包含，前后端版本永不错配，回滚即换回旧二进制。
- 反向代理场景只需转发一个端口，无需维护静态目录与路径映射。

## 后果
- 正面：部署、升级、回滚极简；版本原子性由构建保证；分发只有一个产物需要校验。
- 负面与约束：前端任何变更都需要重新构建后端二进制才能进入交付物（开发态由 Vite dev server 规避）；二进制体积随前端产物增大；构建流水线必须串行化「前端构建 → 后端编译」，该顺序错误属于构建脚本缺陷，需在质量门禁中防护。

## 备选方案
- 静态目录旁挂（运行时从磁盘目录读取前端产物）：部署需同步两份产物，版本可能错配，升级与回滚不再原子。
- 独立前端服务（Node/独立静态服务器另起进程）：直接违背「部署不需要独立前端服务」的硬要求，增加运维面与故障面。
