# ADR-0008：离线迁移包格式

## 状态
已接受

## 背景
离线迁移场景下无法回源核对，迁移包本身是唯一输入；若包内配置与 blob 不一致、或不同时间点导出的内容被混用，迁移结果会静默缺失且无从发现。因此离线包的完整性与一致性必须由格式本身保证，而不能依赖操作纪律。

## 决策
- 完整离线迁移包必须包含**版本化权威清单**，至少覆盖：仓库配置、group 成员关系、proxy 上游配置、资产/缓存清单、blob 校验信息。
- 清单携带格式版本号、源实例标识、快照时间；包内所有内容必须属于**同一一致性快照**。
- 包携带**整体摘要校验**；导入时先验整体摘要，再逐对象验校验和。
- **跨快照混用阻断**：清单与 blob 来自不同快照时，必须被整体摘要或对象校验阻断导入，不得部分吞下。
- 导出必须在源端停写/只读窗口内完成，或采用「首轮导出 + 最终增量核对」达到同一快照一致性；导出失败不得产出可被误用的完整包。

## 理由
- 权威清单是「全量成功」结论的前提：没有清单就只能尽力恢复（ADR-0007 的降级路径）；清单与 blob 同快照才能保证「清单说有、包里必有」。
- 整体摘要把「混用、篡改、损坏、截断」统一收敛为一个可机器判定的阻断条件，验收时可用「故意混入另一快照的清单或 blob」直接测试。
- 格式版本号使包结构可以向前演进，导入端可以精确拒绝不认识的版本而非误读。

## 后果
- 正面：离线迁移可以给出与在线迁移同等强度的完成结论；包的可验证性成为独立的验收项。
- 负面与约束：导出流程本身成为第一期交付物（M1-FR-041），需要停写窗口配合；包格式一旦发布即是对外契约，演进必须走版本号且保持导入端对旧版本的明确行为。

## 备选方案
- 直接消费 Nexus 原生备份或 blob 目录：无权威清单与一致性保证，只能走尽力恢复降级，不能承诺全量。
- 无整体摘要的松散文件集合：无法检测跨快照混用与传输损坏，一致性靠人工纪律，必然出事。
- 仅清单不含 blob 数据：导入时仍需在线回源拉取，不满足离线场景的定义。
