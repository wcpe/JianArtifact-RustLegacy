# ADR-0007：Nexus 迁移策略

## 状态
已接受（「双入口与默认路径」经 ADR-0015 调整：首选改为离线直读 Nexus 原生数据目录，在线 REST 降为备选，配置来源扩展为 REST 或手动补；本 ADR 的支持矩阵、全量成功完成定义、在线一致性与双校验/幂等判据仍有效）

## 背景
第一期核心卖点是承接存量 Nexus OSS 中 Raw/Maven/npm 仓库的完整迁移与切换。迁移结论直接决定用户敢不敢下线源 Nexus，因此「成功」的语义必须严格、可验证，宽泛的版本承诺与恢复性推断都会造成切换后才暴露的缺失。

## 决策
- **支持矩阵收窄**：仅正式支持并真机验收 Nexus Repository OSS 3.70.x；矩阵之外的版本、数据库代际、对象存储后端在发现阶段明确阻断或标记为实验性，不得静默按 3.70.x 处理。
- **双入口**：在线来源（REST API + 格式协议端点 + blob 下载）与完整离线迁移包（见 ADR-0008）。
- **裸 blob store 明确降级**：仅能尽力恢复可明确归属 Raw/Maven/npm 路径的内容；不凭路径猜测 proxy 上游凭据或 group 成员关系；无权威配置的仓库标记「配置待补充」或「不可全量迁移」；任务总状态不得为全量成功。
- **全量成功（succeeded）完成定义**：
  - 零显式放弃、零未迁移受支持对象、零未解决配置项；任何排除、不可迁缓存、凭据未映射或配置不完整都必须落 partial 并逐项计数。
  - hosted 制品的源字节与目标字节校验一致，且协议元数据（Maven metadata/checksum sidecar、npm packument/dist-tag 等）独立通过校验——**字节 + 协议元数据双校验**。
  - 在线来源完成「首轮搬运 → 源端停写/只读窗口 → 最终增量扫描」，最终清单零未处理漂移；源端删除不自动传播，删除项显式列入切换报告由管理员决定。
  - 对同一未变化来源二次执行时，迁移数为零，所有受支持对象精确计为幂等跳过，不产生重复索引或孤儿 blob。

## 理由
- 版本矩阵收窄使真机验收可以穷尽；「支持一切版本」等于隐性不承诺。
- 恢复性推断出的「全量成功」是最危险的结果——用户据此切换后才发现缺失；宁可显式 partial 并给出补救清单。
- 双校验防止「文件字节在、客户端不可用」的假成功；二次执行零迁移是幂等性的直接可验收判据。

## 后果
- 正面：succeeded 结论可信，可作为切换决策依据；验收标准（真实 3.70.x 源、漂移注入、二次执行）可直接执行。
- 负面与约束：严格完成定义使更多任务落 partial，报告必须清晰引导逐项补救；仅承诺 3.70.x 会将旧版本源用户挡在实验性通道；停写窗口要求源端运维配合。

## 备选方案
- 宽版本范围支持：无法真机穷举验收，承诺不可兑现。
- 仅在线单入口：无法覆盖网络隔离与跨环境搬迁场景。
- 裸 blob 视同完整来源：凭路径猜测配置会产生错误拓扑与凭据映射，被需求明确禁止。
- 抽样校验代替全量结论：与完成定义直接冲突，明确排除。
