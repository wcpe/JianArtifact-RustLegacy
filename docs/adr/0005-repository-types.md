# ADR-0005：仓库类型模型（hosted/proxy/group）

## 状态
已接受

## 背景
第一期必须支撑 Raw/Maven/npm 的托管、上游代理与聚合访问，且 Nexus 全量迁移要求保留源端「hosted/proxy/group」拓扑，迁移后客户端不改仓库结构即可切换。group 场景还叠加了严格的授权约束：无权成员对调用方必须完全不可见。

## 决策
- 仓库类型固定三种：
  - **hosted**：本地托管，接收上传、流式存储、下载、删除、浏览、校验和、覆盖策略与分页索引。
  - **proxy**：配置上游，缓存未命中回源、单飞合并、流式落盘、缓存命中、上游错误分类与超时处理。
  - **group**：只读聚合多个成员仓库。
- group 语义：先校验调用方对 group 本身的 read 权限，再**只对调用方有 read 权限的成员**按成员顺序执行查找与聚合——Raw 顺序命中、Maven metadata 聚合、npm packument 合并。
- 无权成员做到零泄露：其名称、坐标、版本、dist-tag、数量与错误原因均不得出现在任何响应中。
- 对 group 的写入请求一律返回「不支持」。

## 理由
- 三类型与 Nexus 拓扑一一对应，使全量迁移可以保留仓库结构与成员顺序（M1-FR-027）。
- group 只读消除了写路由歧义（写到哪个成员），与 Nexus 行为一致。
- 「按调用方过滤成员」是私有资源零泄露原则（ADR-0004）在聚合场景的必然延伸：group 可读不等于成员可读。

## 后果
- 正面：覆盖第一期全部使用与迁移场景；三类场景（可读 group + 部分成员可读 / 全部成员不可读 / 不可读 group）可按验收标准逐一测试。
- 负面与约束：group 聚合需按格式定义版本冲突与 dist-tag 优先级规则（归各格式协议规格）；成员授权上下文必须批量装配，避免逐成员查询；group 响应因按调用方过滤而不可全局缓存，缓存键必须含调用方可读成员集。

## 备选方案
- 不做 group：Nexus 迁移无法保留拓扑，用户切换时必须改所有客户端的多仓库配置，违背「迁移后直接切换」目标。
- group 支持写入路由（写第一个可写成员等策略）：语义歧义大、排错困难，Nexus 亦不支持，明确排除。
- 更高级的虚拟仓库策略（跨成员 metadata 深度聚合、规则路由）：属后续分期，不在本期预留。
