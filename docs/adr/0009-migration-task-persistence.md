# ADR-0009：迁移任务持久化与状态机

## 状态
已接受

## 背景
迁移是长时间运行的异步任务，必须支持暂停、继续、取消、重试，服务或浏览器重启后历史与进度仍可查询，且对同一来源重跑必须幂等。若任务状态只在内存中，任何重启都会丢失历史，违背验收要求「服务中途重启后任务显示已中断、可一键重跑续传」。

## 决策
- 异步任务状态机固定十态：`queued / running / pausing / paused / cancelling / cancelled / succeeded / partial / failed / interrupted`；仅零排除、零未迁移受支持对象、零未解决配置项时可进入 `succeeded`。
- 持久化全部落 SQLite（沿用 ADR-0002 的唯一真源），使用**任务表 + 分仓明细表**结构：任务、不可变参数快照、节流写入的进度与对象检查点、按仓库的明细报告、有界失败样本。
- **幂等键 = 稳定源标识 + 目标路径 + 内容校验**；重跑只处理未完成、失败或内容变化的对象，已一致对象精确计为跳过。
- 暂停/取消只在**单对象原子提交边界**生效：取消清理未提交的临时文件，但不删除已成功提交且被引用的数据。
- 服务重启时，处于在途状态（running/pausing/cancelling）的任务一律标记为 `interrupted`，可续传重跑。

## 理由
- 显式的过渡态（pausing/cancelling）消除「已请求取消但仍在写」的歧义，使控制操作的语义可测试；`interrupted` 与 `failed` 区分「进程原因」与「任务原因」。
- 不可变参数快照保证报告可复现任务当时的完整配置与冲突决策；有界失败样本防止大规模失败撑爆数据库。
- 对象级检查点 + 幂等键使续传不重不漏，「二次执行迁移数为零」（ADR-0007）成为可直接断言的结果。
- 原子边界控制与 ADR-0002 的提交顺序共同保证任何暂停、取消、崩溃都不产生可见半成品索引。

## 后果
- 正面：重启恢复、幂等续传、报告持久化全部可按验收标准逐条测试；状态机可穷举单元测试。
- 负面与约束：逐对象检查点带来持久化写入压力，进度写入必须节流、批量，且不得在持锁期间执行；状态迁移必须集中定义，禁止散落各处的状态赋值。

## 备选方案
- 内存任务 + 日志重放：重启即丢历史与进度，违背持久化验收要求。
- 外部任务队列（Redis 等中间件）：引入外部依赖，违背零外部依赖的运行形态。
- 粗粒度检查点（按仓库而非按对象）：中断后需整仓重跑，无法精确计数跳过，幂等验收无法达成。
