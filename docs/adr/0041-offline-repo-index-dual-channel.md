# ADR-0041：离线迁移仓库索引双通道（REST 权威优先 + 纯离线推断回退）

## 状态

已接受

> 扩展 ADR-0006（制品库迁移入口）：细化其「离线 blob store 入口」的仓库索引获取方式，不推翻双入口框架。

## 背景

Nexus 迁移重做（M4）要求离线迁移先获取**仓库索引**（仓库列表及其格式 / 类型 / 上游配置），展示给管理员选择后再搬运。障碍在于：

- 迁移源为 Nexus OSS 3.70.x，仓库配置存在嵌入式 **OrientDB**（3.71+ 才换 H2）；OrientDB 的 plocal 二进制格式无 Rust 读取库，逆向解析工程量极大且跨版本脆弱。
- blob store 文件系统里每个 blob 的 `.properties` 含仓库名 / 内容路径 / sha1 / 大小，足以**枚举仓库与内容清单**，但**不含**仓库的格式、类型（hosted/proxy）、上游 URL 等权威配置。

## 决策

离线迁移的仓库索引阶段采用**双通道**，向导内按可达性自动选路：

- **通道一（权威，优先）**：管理员可选填源 Nexus 的 REST 地址与凭据引用（`auth_ref`，真值走环境变量）；可达时经 `/service/rest/v1/repositories` 获取权威仓库配置（名称 / 格式 / 类型 / 上游 URL），与离线 blob store 扫描结果按仓库名对齐合并（配置来自 REST、blob 数与大小来自扫描）。
- **通道二（推断，回退）**：未填地址或探测不可达时，纯离线扫描 blob store 枚举仓库，并按内容路径**启发式推断格式**：Maven 坐标目录布局 → maven2；npm 包 tarball / `package.json` 元数据路径 → npm；docker v2 内容寻址布局 → docker；其余 → raw 兜底。推断结果在索引中**标注来源为「推断」**，仓库类型与上游 URL 留空，由管理员在向导的仓库选择步骤补填 / 修正。
- **统一索引结构**：两通道输出同一份仓库索引（名称、格式及其来源〔权威 / 推断〕、类型、blob 数、总大小、上游 URL），供向导多选与后续搬运消费。
- **不解析 OrientDB / H2 数据库文件**：明确排除，见备选。

## 理由

- 双通道兼顾两种真实场景：源 Nexus 还能临时起来时拿权威配置（准确、免手填）；源已停机 / 只剩 blob store 备份时仍可迁（推断 + 人工补填兜底）。
- 推断只做启发式且显式标注来源，把「猜错」的风险交给人工确认环节消化，不冒充权威数据。
- 通道一复用既有在线迁移的 REST 客户端与凭据机制（`auth_ref` + 环境变量），无新依赖、凭据红线不变。

## 后果

- 正面：离线迁移在源可达与不可达两种形态下都能产出可选择的仓库索引；权威通道下类型 / 上游无需手填。
- 负面 / 约束：推断通道对 blob store 目录布局有隐式依赖（既有离线枚举已有此风险，跨 Nexus 版本需维护）；格式推断存在误判可能，需向导侧允许人工修正；双通道使索引阶段多一次可达性探测。

## 备选方案

- **解析 OrientDB plocal 文件**：无 Rust 库、格式无文档、逆向脆弱且跨版本不可控。落选。
- **要求用户先从 Nexus 导出数据库（JSON/SQL）再解析**：需要临时起 Java 环境跑导出工具，运维门槛高于直接临时启动 Nexus 走 REST 通道，且已停机场景同样无法满足。落选。
- **仅纯离线推断（单通道）**：源可达时也拿不到权威类型 / 上游，全部依赖手填，体验差且易错。落选。
- **仅 REST（单通道）**：源永久下线、只剩 blob store 备份时无法迁移，砍掉了离线入口的核心价值。落选。
