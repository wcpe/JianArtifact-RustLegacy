# ADR-0002：SQLite 元数据唯一真源与文件系统 blob 存储

## 状态
已接受

## 背景
制品仓库需要同时管理结构化元数据（用户、仓库、资产索引、任务）与大体积二进制内容，产品定位是零外部依赖、低运维的单机部署。大文件必须流式处理，且进程在任意时刻崩溃都不得留下可见的半成品索引。

## 决策
- SQLite 是元数据唯一真源；blob 本体存放在本地文件系统数据目录。
- blob 采用 sha256 内容寻址命名，按哈希前两位分桶目录存放。
- 写入顺序不变量：**临时写入 → 校验 → 原子提交 blob → 提交元数据**；配提交守卫防孤儿——blob 落盘成功但元数据未提交时，该 blob 可被识别、可被回收，且不会被正常读取路径命中。
- 元数据库只记录索引、状态、大小与校验信息，不存二进制内容。

## 理由
- 内容寻址天然提供跨仓库去重与完整性校验；分桶避免单目录条目过多。
- 「先 blob 后元数据」保证数据库中任何可见索引指向的 blob 必定存在；崩溃只会留下可回收的临时文件或未被引用的 blob，不会出现指向缺失内容的索引。
- 嵌入式 SQLite + 本地文件系统使备份即「复制数据库文件 + 数据目录」，符合低运维定位。

## 后果
- 正面：零外部依赖；崩溃一致性可由故障注入测试验收；去重与校验为迁移的幂等跳过（ADR-0009）提供基础。
- 负面与约束：需要孤儿 blob 的识别与回收机制；SQLite 单写者特性要求写事务保持短小，禁止持锁执行网络或磁盘长耗时操作；同一 blob 的写入、索引提交与清理必须有明确所有权，禁止竞争删除仍被引用的内容；对象存储后端属后续分期，不得在本期预留半成品。

## 备选方案
- 外部数据库（PostgreSQL/MySQL）：引入强制外部依赖，违背默认轻量运行形态。
- 对象存储（S3 兼容）：同样引入外部依赖，且第一期明确列为非目标。
- 数据库内存二进制（BLOB 列）：大文件流式读写能力差，数据库文件膨胀，备份与校验笨重。
