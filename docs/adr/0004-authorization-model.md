# ADR-0004：授权模型

## 状态
已接受

## 背景
第一期要求仓库级权限控制：匿名只读公开仓库、普通用户按仓库授权访问、管理员全局管理；验收标准要求穷举「匿名 / 普通用户 / ACL 用户 / Admin × public/private × 读/写/管理」矩阵，且对无权限私有资源不得泄露存在性（包括列表、搜索与计数侧信道）。

## 决策
- 仓库可见性两种：public / private。匿名仅可读 public 仓库。
- 仓库 ACL 至少含 read、write、admin 三类动作，按用户授予。
- 全局角色两种：Admin / User；Admin 全局可管理所有仓库与用户。
- 对无权限的私有资源，返回与「不存在」完全一致的响应；名称、坐标、版本、数量等一律不出现在任何列表、搜索结果或错误信息中。
- 授权判定实现为**无 IO 纯函数**：输入为主体（身份、角色、启用状态）、资源（仓库、可见性、ACL）与动作的完整上下文，输出允许/拒绝；函数内部不查数据库、不发网络请求。

## 理由
- 纯函数使授权矩阵可以被穷举单元测试，直接对应验收标准；判定逻辑集中一处，管理 API 与格式协议端点复用同一实现，杜绝各端点自行查库判权导致的不一致。
- 「私有资源等同不存在」必须在模型层统一约定，才能防止个别端点以 403 与 404 的差异泄露存在性。
- 两角色 + 三动作是覆盖第一期需求的最小模型，不提前泛化。

## 后果
- 正面：授权逻辑可测试、可审计、可复用；架构门禁可检查「React 页面自行实现鉴权判定」「协议层旁路授权」等违规。
- 负面与约束：调用方必须先装配授权上下文（用户状态、仓库 ACL）再调用判定函数，装配层需批量加载，避免循环内逐项查询；group 聚合场景需为每个成员装配上下文（见 ADR-0005）。
- 前端隐藏按钮只是体验优化，一切拒绝以后端判定为准。

## 备选方案
- 带角色继承的通用 RBAC：第一期两角色三动作已足够，提前泛化引入无实际用途的结构。
- 授权条件内嵌 SQL 查询：逻辑分散且无法穷举测试，与纯函数目标相悖。
- 外部策略引擎 / 策略 DSL：新增依赖与学习成本，与项目规模不匹配。
