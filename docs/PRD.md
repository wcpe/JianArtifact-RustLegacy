# 产品需求文档（PRD）：JianArtifact

> 本文档是需求的单一真源（WHAT / WHY），也是产品的**需求登记册 + 路线图**——全生命周期持续维护，不是一次性文档。每个需求在 §4 登记一行 FR（带期与状态），交付即标版本；§4 FR 登记册是迭代中最常变动的部分，分期（§7）只是其中很小、很静的一页粗线条规划。单个功能的详细规格放 `docs/specs/`，PRD 只保留“一行 FR + 验收摘要 + 状态”的索引级信息。

> 项目基线：许可证 MIT；版本起点 0.1.0。

## 1. 背景与目标

### 1.1 产品定位与核心价值

JianArtifact 是一个以**低运维成本**为目标的自托管制品仓库，面向个人、研发团队和中小型组织，统一管理多种包格式的 hosted、proxy 与只读 group 仓库。

核心价值：

- 使用一个服务统一托管和代理常见开发制品。
- 保持包管理器原生协议兼容，不要求开发者安装专用客户端。
- 提供多用户、仓库级权限和 Web 管理界面。
- 第一版即可承接存量 Nexus Repository OSS 中 Raw、Maven、npm 仓库的完整迁移和切换。
- 默认采用嵌入式元数据与本地 blob 存储，避免强制依赖外部数据库、中间件或对象存储。

### 1.2 技术与交付基线

以下选型为已拍板决策，实现与规格文档不得偏离；变更须先立 ADR：

| 维度 | 决策 |
|---|---|
| 后端 | Rust：axum 0.8 + tokio + sqlx（SQLite，bundled）+ argon2 + JWT（HS256）+ reqwest（rustls） |
| 后端硬约束 | 零系统级 C 库依赖（不依赖系统 OpenSSL / sqlite3，SQLite 经 bundled 编译期内嵌）；crate 级 `unsafe_code = "forbid"` |
| 前端 | React + TypeScript strict + Vite + shadcn/ui + Tailwind CSS + TanStack Table |
| 工作区 | pnpm workspace + Turborepo；Rust 侧 Cargo workspace |
| 交付形态 | rust-embed 内嵌前端产物，单二进制交付 |
| API 契约 | utoipa 生成 OpenAPI，作为管理 API 契约的唯一真源 |
| 许可证 / 版本 | MIT；版本起点 0.1.0 |

### 1.3 第一期目标

第一期完成后，团队能够：

1. 部署一个新的 JianArtifact 实例并创建首个管理员。
2. 创建和管理多个用户。
3. 创建 Raw、Maven、npm 的 hosted、proxy 仓库，以及用于保留 Nexus 拓扑的只读 group 仓库。
4. 使用 curl、Maven 和 npm 原生客户端发布、代理和下载制品。
5. 从在线 Nexus OSS 或符合输入契约的完整离线迁移包发现并迁移上述仓库；裸 blob store 仅提供明确降级的尽力恢复。
6. 在服务或浏览器重启后继续查看迁移历史，对中断任务执行幂等续传。
7. 用迁移报告和官方客户端复验迁移结果，然后完成切换。

### 1.4 非目标（第一期）

- 不迁移 Nexus 用户、角色、权限、LDAP/OIDC 配置、任务计划、脚本、邮件、Webhook 或其他系统配置。
- 不支持 Docker/OCI、Cargo、PyPI、Go、NuGet、RubyGems、Conan、Terraform、Ansible、Pub 等协议。
- 不提供 S3/对象存储后端。
- 不提供 LDAP/OIDC 登录。
- 不提供多节点集群、分布式锁或高可用控制面。
- 不提供复杂保留策略、自动 GC、备份恢复编排、漏洞扫描、WAF、CC 挑战或使用分析面板。
- 不为了后续能力在第一期数据库中加入无实际用途的占位字段。

第一阶段之外的格式和企业能力必须进入后续分期，不得以未使用字段、空接口或占位模块提前进入第一期实现。

## 2. 角色

### 2.1 匿名访问者

- 只能读取允许匿名访问的公开仓库。
- 不能写入制品、查看私有仓库、进入管理端或读取迁移报告。
- 对无权限私有资源不得泄露其存在性。

### 2.2 普通用户

- 使用用户名和密码登录 Web 管理端。
- 可创建、查看和吊销自己的 API Token。
- 按仓库 ACL 使用包管理器或 HTTP 客户端读取、发布制品。
- 只能查看自己有权访问的仓库、制品和搜索结果。

### 2.3 管理员

- 管理用户、用户状态和全局角色。
- 创建、修改、停用和删除仓库。
- 管理仓库可见性及用户级 ACL。
- 发起、暂停、继续、取消和重试 Nexus 迁移任务。
- 查看迁移进度、历史、校验结果和失败明细。

### 2.4 包管理器与自动化客户端

- Maven、npm、curl 等客户端通过原生协议访问。
- 支持适合 CLI 的 Basic Auth、Bearer/API Token 鉴权。
- 客户端无需理解 JianArtifact 的内部管理 API。

## 3. 用户故事

- 作为部署者，我希望用单个二进制文件启动服务并通过一次性自举流程创建首个管理员，以便在无外部依赖的环境中快速上线。
- 作为管理员，我希望创建用户、禁用账号并调整角色，以便控制团队成员对制品仓库的访问。
- 作为管理员，我希望创建 Raw/Maven/npm 的 hosted、proxy、group 仓库并配置可见性与 ACL，以便按项目和团队隔离制品读写权限。
- 作为普通用户，我希望签发和吊销自己的 API Token，以便在 CI 与命令行中安全地发布和拉取制品。
- 作为开发者，我希望直接使用 curl、Maven、npm 原生客户端与仓库交互，以便不改变既有构建流程。
- 作为管理员，我希望通过 Web 向导从在线 Nexus 实例或完整离线迁移包发现并迁移 Raw/Maven/npm 仓库，以便一次性完成存量制品库的搬迁与切换。
- 作为管理员，我希望迁移任务可暂停、取消、重试并在服务重启后幂等续传，以便大规模迁移不因中断而重来。
- 作为管理员，我希望获得按仓库细分、可复核的迁移报告，以便用官方客户端复验后放心切换。
- 作为匿名访问者，我希望匿名拉取公开仓库中的制品，以便消费开放依赖而无需注册账号。

## 4. 功能需求（FR）

### 4.1 Nexus 支持矩阵与输入契约

第一期正式支持矩阵：

| 维度 | 第一期承诺 |
|---|---|
| 产品 | Nexus Repository OSS |
| 版本 | 3.70.x |
| 仓库格式 | Raw、Maven2、npm |
| 仓库类型 | hosted、proxy、group |
| 在线来源 | REST API、格式协议端点和 blob 下载能力均可访问的运行实例 |
| 离线来源 | JianArtifact 定义的完整离线迁移包：权威仓库清单、group 成员关系、proxy 上游配置、资产/缓存清单、blob 数据与校验信息 |
| blob 后端 | 第一阶段仅承诺文件系统 blob store 的导出与迁移 |
| 不支持 | Nexus 用户、角色、权限、脚本、计划任务、系统配置，以及 Raw/Maven/npm 之外的格式 |

完整离线迁移包必须由受支持的导出流程生成，清单具有版本号和完整性校验。只提供裸 blob store 时：

- 可扫描和迁移能够明确归属到 Raw/Maven/npm 路径的内容。
- 不允许凭路径猜测 proxy 上游凭据或 group 成员关系。
- 无权威配置的仓库必须标记为“配置待补充”或“不可全量迁移”。
- 任务总状态不得标记为“全量成功”。

矩阵之外的 Nexus 版本、数据库代际、对象存储后端或插件格式必须在发现阶段明确阻断或标记为实验性，不得静默按 3.70.x 处理。其他 Nexus 版本只能在兼容性检查通过后作为实验性来源，不得承诺全量迁移。

| M1-FR-044 | 前端工程基座与严格静态检查接线 | 四个前端子工程（web/ui/wiki/devmock）脚手架落地；`apps/eslint-config` 与 `apps/typescript-config` 为真实共享配置（ESLint `--max-warnings 0`、TS `strict`+`noUncheckedIndexedAccess`+`isolatedModules`、Prettier 只检不改）；四工程各自独立 typecheck/lint/test/build 全绿并纳入 Docker 质量门；故意引入违规样例能使门禁失败（红→绿证据） | 开发中 |

> 状态取值：计划 / 开发中 / 已交付@vX.Y.Z。
> 标 `已交付` 是有门的：只有该 FR 对应 spec 的验收标准全部满足、对应测试与实机验收通过后，才在发版时统一标 `已交付@vX.Y.Z`——开发/修复过程中不得自行预标。FR 标了 `已交付` 实际是断的（false-done）：功能坏了要修回，走缺陷修复流程把状态归真（从没真正工作过则回退 `开发中`）；需求本身要撤/推迟则走变更回退流程。

### 4.3 Nexus 全量迁移的完成定义

“任务成功”不能只表示 HTTP 请求结束，必须同时满足：

- 只有零显式放弃、零未迁移受支持对象、零未解决配置项时，任务才可标记 `succeeded/全量成功`；任何放弃、缓存无法迁移、凭据未映射或配置不完整都必须标记 `partial` 并逐项计数。管理员显式排除的仓库保留在报告中，不得伪装成从未发现。
- 所有纳入执行且受支持的仓库均已创建或映射到明确目标，冲突决策已持久化。
- 在线来源已完成“首轮搬运 → 源端停写或只读 → 最终增量扫描”，最终清单不存在未处理的新增、修改或删除漂移；JianArtifact 默认不自动传播源端删除，删除项必须在切换报告中显式列出并由管理员决定。
- 离线来源的仓库配置、group 关系、资产/缓存清单和 blob 必须属于同一已验证快照，整体摘要校验通过；跨快照混用或清单与 blob 漂移时不得全量成功。
- hosted 制品的源字节与目标字节校验一致，协议元数据也独立通过校验。
- Maven 保持坐标、release/snapshot 版本、artifact/snapshot metadata 和 checksum sidecar 的客户端可观察语义。
- npm 保持包文档、版本集合、dist-tag、scoped package 和 tarball 可访问性，目标 tarball 地址不得指回源 Nexus。
- proxy 上游配置、有效凭据引用和全部可枚举正缓存均已迁移；每个缓存对象必须被迁移、校验或明确列为未迁移，不能以抽样命中代替全量结论。
- Raw group 按成员顺序命中；Maven group 可聚合后序成员版本与 metadata；npm group 可合并后序成员版本并按已定义规则处理版本冲突和 dist-tag。
- 不支持格式、无法识别 blob、权限不足、源数据损坏、凭据未映射和目标冲突均有稳定错误类别与可定位信息。
- 迁移任务完成后重启 JianArtifact，历史、参数快照、进度和报告仍可查询。
- 对同一源再次执行，所有未变化对象应被精确计为幂等跳过，迁移数为零，且不产生重复索引或孤儿 blob。

## 5. 非功能需求（NFR）

### 5.1 工程组织约束

所有可构建的 Rust crate、React 应用、共享 UI、开发 Mock、配置包和未来内部工具都必须是 `apps/*` 工作区成员；禁止新增 `packages/*`、`services/*` 等第二套子工程根目录。`docs/` 与 `scripts/` 只存正式文档和工程脚本，不属于可构建子工程。此结构为强制约束：

```text
JianArtifact/
├─ apps/
│  ├─ server/             # Rust 后端、管理 API、格式协议、存储与迁移
│  ├─ web/                # React 管理端产品应用
│  ├─ ui/                 # 共享 React 组件、布局、主题与设计令牌
│  ├─ wiki/               # UI 组件与业务模式预览、可访问性验收入口
│  ├─ devmock/            # 浏览器与 Node 双端 Mock、场景包和契约模拟
│  ├─ eslint-config/      # 前端共享 ESLint 严格配置
│  └─ typescript-config/  # 前端共享 TypeScript 严格配置
├─ docs/                  # PRD、ARCHITECTURE、API、ADR、协议规格与运维文档
├─ scripts/               # 质量门、容器化开发与验收入口
└─ 根工作区配置           # Cargo/pnpm/Turbo 等工作区编排文件
```

各子工程职责与边界：

**apps/server**

- 一个 Rust workspace 成员，第一期优先保持单服务、清晰模块分层，不因未来格式扩展提前拆成大量微型 crate。
- 内部至少按职责区分：`domain`、`auth`、`repository`、`storage`、`protocol`、`migration`、`api`、`persistence`、`config`。
- 依赖方向必须单向；协议适配层不得直接读写数据库，必须通过领域服务与仓储接口。
- Rust 生产代码禁止 `unsafe`。
- 大文件上传、下载、代理回源和迁移必须流式处理，不得整体载入内存。

**apps/web**

- React + TypeScript 管理端。
- 只消费管理 API，不在浏览器中复制后端授权规则。
- 页面至少包括：登录、仪表盘、仓库列表、仓库详情与文件浏览、用户管理、Token 管理、迁移向导、迁移任务与报告。
- 所有权限拒绝必须以后端结果为准；前端隐藏按钮只是体验优化，不是安全边界。

**apps/ui**

- 共享设计系统与组件库，产品页不得各自复制基础按钮、表单、弹窗、表格和状态组件。
- 组件分为基础组件、复合组件、页面布局和业务模式四层。
- 不允许依赖 `apps/web`，只允许由 `web` 和 `wiki` 单向依赖。
- 必须覆盖键盘操作、焦点可见性、语义标签、错误提示和基础响应式布局。

**apps/wiki**

- 作为 UI 组件、交互状态和业务模式的独立预览站。
- 展示正常、加载、空数据、错误、无权限、超长文本、大数据量等状态。
- 新增共享组件必须先在 wiki 中建立可复现预览，再进入产品页面。
- 可作为视觉回归和无障碍检查的稳定入口。

**apps/devmock**

- 提供浏览器和 Node 两种运行方式。
- 使用与真实管理 API 一致的请求/响应契约，提供有状态内存数据。
- 至少包含：默认数据、空实例、权限受限、上游失败、迁移进行中、迁移部分失败、大仓库分页等场景包。
- `web` 在显式开发开关下可连接 devmock；生产构建必须默认关闭且不得打包测试凭据。
- devmock 契约测试必须防止其与真实后端 API 漂移。

### 5.2 运行形态

第一期默认运行形态：

- 一个 Rust 服务进程。
- 一个 SQLite 元数据库。
- 一个本地文件系统 blob 数据目录。
- React 静态产物经 rust-embed 内嵌，由 Rust 服务进程直接提供，单二进制交付；部署时不需要独立运行前端服务或 Node 运行时。
- 可置于反向代理之后完成 TLS 终止。

### 5.3 数据硬原则

- SQLite 是元数据唯一真源。
- blob 本体默认存放在文件系统，元数据库只记录索引、状态、大小和校验信息。
- 所有写入采用“临时写入 → 校验 → 原子提交 blob → 提交元数据”的顺序。
- 数据库迁移只允许向前追加；破坏性 Schema 变更必须先写 ADR 和迁移方案。
- 密码、Token、JWT 密钥、Nexus 凭据不得明文落库或进入日志。

### 5.4 并发硬原则

- 同一 proxy 仓库、同一路径的并发缓存未命中必须单飞合并。
- 同一 blob 的写入、索引提交和清理必须有明确所有权，禁止竞争删除已被其他制品引用的内容。
- 不得在持锁期间执行网络、磁盘或数据库长耗时操作。
- 迁移任务必须有限并发，避免挤占正常上传、下载和代理请求资源。

### 5.5 NFR 数值摘要（已钉死）

数值的**权威定义、形态（配置项/常量/验收目标）与验收证据要求**见 `docs/specs/m1-nfr.md`（编号 NFR-01~16，2026-07-12 定稿），本节仅为摘要；相关实现与测试引用 NFR 编号：

| 项 | 摘要 |
|---|---|
| 大文件大小 | 最大单制品 5 GiB（NFR-01），大文件验收以 5 GiB 样本为基准 |
| 最大单请求缓冲 | 流式缓冲块 8 MiB、单请求内存缓冲 16 MiB；npm publish 体为唯一例外，上限 128 MiB（NFR-02~04） |
| 并发数 | 验收负载 50 并发；单飞验收 32 并发；迁移对象并发默认 4、上限 8（NFR-07~09） |
| 内存上限 | 常驻 ≤ 256 MiB；负载与大文件峰值 ≤ 1 GiB，单大文件 RSS 增量 ≤ 256 MiB（NFR-05~06） |
| 磁盘保留 | 剩余 < 5 GiB 或 < 5% 即停写；迁移空间估算系数 1.1（NFR-11~12） |
| 迁移规模 | 验收 ≥ 10 万对象 / ≥ 100 GiB（含 5 GiB 大对象、清单 > 2 页）；重跑全跳过 ≤ 30 分钟（NFR-13~15） |
| 列表分页 | 默认页大小 50、最大 200（NFR-16） |

## 6. 验收标准

以下四块为第一期整体“做完”的可验证判据；凡涉及真实客户端、真实 Nexus 源或真实环境的验收项，**必须以实机证据为准并由用户确认通过**——测试绿不替代真的能用。

### 6.1 认证与授权

- 穷举匿名、普通用户、仓库 ACL 用户、Admin 对 public/private 仓库的读、写、管理矩阵。
- 被禁用用户的会话和 Token 立即失效。
- Token 吊销后下一次请求立即失败。
- 无权限搜索和浏览结果不得包含私有仓库名称、坐标或数量侧信道。

### 6.2 原生客户端互通

必须在隔离的真实环境中完成：

- Raw hosted：curl 上传、下载、覆盖和删除。
- Raw proxy：首次回源、第二次缓存命中、上游失败分类。
- Maven hosted：`mvn deploy` 与依赖获取，覆盖 release/snapshot。
- Maven proxy：从公开上游解析并缓存依赖。
- npm hosted：`npm publish` 与 `npm install`，覆盖 scoped package。
- npm proxy：首次上游安装、离线上游后的缓存安装。
- Raw group：先校验 group read，只按调用方可读成员顺序命中路径；无权成员被跳过而不泄露。
- Maven group：metadata 只聚合调用方可读成员；后序可读成员独有版本可由 Maven 客户端下载，冲突按既定优先级处理。
- npm group：packument 只合并调用方可读成员；可安装后序可读成员独有版本，dist-tag、版本冲突和 tarball 地址改写符合既定规则。
- group ACL 组合：分别验证“可读 group + 部分成员可读”“可读 group + 全部成员不可读”“不可读 group”三类场景，任何响应都不得泄露无权成员的名称、坐标、版本、dist-tag、数量或错误原因。

### 6.3 Nexus 迁移

至少准备一个真实 Nexus OSS 3.70.x 验收源，包含：

- Raw hosted、Raw proxy、Raw group。
- Maven hosted、Maven proxy、Maven group。
- npm hosted、npm proxy、npm group。
- 每个 group 至少两个成员，并在后序成员放置前序成员没有的版本或路径；另准备同版本冲突和 dist-tag 冲突样本。
- 正常制品、重复内容、损坏或不可读样本、目标同路径不同校验样本、大文件和跨多页资产清单。

在线与离线入口都必须分别验收：

1. 在线来源和完整离线迁移包的发现结果均与 Nexus 实际仓库列表、类型和成员顺序一致；裸 blob 模式必须明确降级。
2. 在 Nexus 停写/只读窗口生成离线包，并故意混入另一快照的清单或 blob：完整快照可导入，混合快照被整体摘要或对象校验阻断。
3. 管理员可选择仓库、改目标名、映射上游凭据引用并预览冲突。
4. 默认禁止覆盖；同校验冲突被跳过，不同校验冲突在未获显式决策前阻断执行。
5. 迁移过程中可刷新浏览器；在大对象传输期间触发暂停、取消或服务终止，不产生可见半成品索引，随后可继续或重试。
6. 服务中途重启后任务显示“已中断”，可一键重跑续传。
7. 在线迁移期间在源端新增、修改和删除样本；首轮后进入停写窗口并执行最终增量扫描，报告准确列出并处理全部漂移。
8. 对未变化来源执行第二次迁移时，迁移数为零，受支持对象全部计为校验一致跳过。
9. 迁移后的 Raw、Maven、npm hosted 与三类 group 均由官方客户端读取成功，后序 group 成员中的版本可见且可下载。
10. 迁移后的 proxy 正缓存逐对象计数与清单一致，并可在断开源 Nexus/上游后命中；不得只做抽样即宣称全量。
11. 报告按仓库给出资产与协议元数据状态、缓存记录数、blob 数、数量、字节、耗时、凭据引用状态和有界失败明细。
12. 非支持格式、配置不完整仓库和未迁移对象被列入清单，整体结果不得误标为无损全成功。

### 6.4 性能与可靠性

- 正式 M1 NFR 规格必须在实现前钉死大文件大小、最大单请求缓冲、并发数、内存上限、磁盘保留空间和迁移数据规模；缺少这些数值时不得开始相关实现。
- 大文件验收必须证明上传、下载、代理和迁移的缓冲上限固定，不随对象总大小线性增长，并输出峰值内存证据。
- 相同 proxy 路径的并发未命中测试必须使用已定义的并发数，并只产生一次有效上游拉取。
- 进程异常终止不得留下可见的半成品索引；临时文件可识别、可回收且不会被正常读取路径命中。
- 迁移计划必须给出目标空间估算；运行中按配置的最小剩余字节或剩余比例阈值停止接收新对象，当前原子对象完成后进入可恢复失败态。
- 列表和发现接口必须分页；验收数据量至少超过两个完整页，并验证遍历无重复、无遗漏。

## 7. 分期（路线）

各期只描述主题与目标；具体哪个 FR 属于哪期，以 §4 FR 登记册的编号前缀（如 M1-FR-）为唯一来源——加需求即在表里按期编号，本节不重复列编号。某期是否完成，看 §4 表里该期 FR 的状态是否都 `已交付`。

M1 期内的交付工序（前端/mock 先行、契约骨架、阶段门禁）以 `docs/ROADMAP.md` 为唯一真源（依据 ADR-0014），本节不重复描述。

- **M1（第一期，MVP）：可迁移的核心制品库。** 多用户认证与授权、Raw/Maven/npm 的 hosted/proxy/group 仓库、原生客户端互通、Nexus 仓库全量迁移（在线 + 离线）、Web 管理端与迁移向导。
- **M2：高频格式扩展。** Docker/OCI hosted、proxy 与 group；Cargo sparse registry；PyPI；Go modules proxy；NuGet；Nexus 对上述已实现格式的迁移扩展；全局跨仓库搜索和更完整的制品详情。**进入 M2 的前提：M1 三格式原生客户端、在线/离线 Nexus 迁移和重启续传全部通过真实环境验收。**
- **M3：企业认证、存储与运维。** OIDC、LDAP；用户组与更细粒度权限动作；S3 兼容对象存储；审计日志与 Prometheus 指标；备份与恢复；GC、保留策略、配额和存储清理；出站代理、在线配置和受控的运行时管理。
- **M4：安全、供应链与运营可见性。** 多维限流、连接与并发限制、慢速请求防护；IP 名单、异常检测和应用层防护；本地漏洞库镜像与 Maven/npm/Cargo/PyPI/NuGet 坐标匹配；Docker 镜像层扫描；使用分析、容量趋势、缓存命中率和运维告警；迁移和仓库运行状态的长期趋势分析。
- **M5：长尾格式与成熟期能力。** RubyGems、Conan、Terraform、Ansible Galaxy、Dart/Flutter Pub 等长尾格式；高级虚拟仓库策略、跨成员 metadata 聚合；多节点只读扩展或高可用方案（必须先有独立 ADR，不在单节点模型中预留半成品）；面向大型部署的外部数据库或分布式存储可选方案（不得破坏默认轻量运行形态）。

## 8. 质量与流程门禁摘要

以下为门禁要点摘要，可执行细则以 `.claude/rules/` 下的规则文件为准。

### 8.1 通用门禁

任何变更合并前必须通过：格式检查；编译或构建检查；静态分析（警告视为失败）；单元测试、集成测试和受影响的协议测试；API/Mock 契约一致性检查；架构依赖方向检查；敏感信息扫描；依赖漏洞与许可证检查；文档漂移检查（FR、API 或行为变化必须同步正式文档）。

### 8.2 Rust 门禁

- `rustfmt --check`；`clippy` 全 targets、全 features，警告视为错误。
- crate 级 `unsafe_code = "forbid"`。
- 对 panic、unwrap/expect、阻塞 IO、锁跨 await、未处理结果等建立严格 lint 规则或白名单审查。
- 单元测试、存储集成测试、协议兼容测试、迁移测试全部在隔离环境运行。
- 依赖安全、许可证和重复依赖版本必须有机器检查。

### 8.3 React/TypeScript 门禁

- Prettier 只检查不自动改写的 CI 模式；ESLint `--max-warnings 0`，共享配置由 `apps/eslint-config` 提供。
- TypeScript 启用 `strict`、`noUncheckedIndexedAccess`、`isolatedModules`，禁止以大范围 `any` 绕过类型系统。
- `apps/web`、`apps/ui`、`apps/wiki`、`apps/devmock` 均必须独立 typecheck、lint、test、build。
- 组件测试覆盖交互、错误态和权限态；关键用户流程使用真实浏览器 E2E。
- devmock 与后端 OpenAPI/契约模型必须自动比对，不得手工长期漂移。

### 8.4 架构审查阻断项

自动或审查规则至少阻断：`ui` 反向依赖 `web`；协议 handler 直接访问 SQLite；React 页面自行实现鉴权判定并替代后端授权；循环依赖；在循环中逐项查询数据库或逐项创建 HTTP 客户端；持锁执行网络、磁盘或数据库 IO；大文件整体读入内存；生产代码中的临时打印、英文日志或敏感值日志。

### 8.5 容器化验证约束

- 宿主机不得直接运行 `cargo`、`pnpm`、`npm`、构建或测试命令；构建、测试、lint、typecheck、协议测试统一在 Docker 中执行。
- Rust `target`、前端 `node_modules`、包管理器缓存和测试产物使用 Docker volume 或容器临时目录，不写入宿主项目目录。
- 不创建 git worktree 作为并行开发或测试手段。
- CI 与本地 Docker 质量入口必须使用同一组脚本，避免“本地通过、CI 不同命令失败”。

## 9. 测试策略

### 9.1 测试先行

- 每个功能变更必须先有可复现的失败测试。
- 修复缺陷必须先提交能稳定复现根因的回归测试。
- 不允许通过删除、跳过、放宽断言或隐藏错误使测试通过。
- 协议实现以客户端可观察行为为测试对象，不只测试内部函数。

### 9.2 测试层次

1. 领域单元测试：权限、覆盖策略、路径规范化、状态机、迁移计数。
2. 持久化集成测试：事务、并发、迁移脚本、幂等写入、重启恢复。
3. 协议测试：HTTP 请求/响应、状态码、头、metadata、checksum。
4. 官方客户端测试：curl、Maven、npm。
5. Nexus 迁移测试：合成 fixture + 真实 Nexus OSS 3.70.x。
6. 前端组件测试：共享组件、表单、权限态、错误态。
7. 浏览器 E2E：登录、建仓、授权、发布/浏览、迁移向导、重启后恢复。
8. 竞争与故障注入：并发缓存未命中、断流、磁盘不足、DB 提交失败、进程中断。

## 11. 术语表

| 术语 | 说明 |
|---|---|
| hosted 仓库 | 由 JianArtifact 直接托管制品本体的仓库，接受客户端上传与发布。 |
| proxy 仓库 | 代理远端上游仓库的只读仓库，按需回源并在本地缓存。 |
| group 仓库 | 按固定成员顺序聚合多个成员仓库的只读虚拟仓库，不接受写入。 |
| blob | 制品或缓存对象的二进制本体，存放于本地文件系统，元数据库只记录索引与校验信息。 |
| 正缓存 | proxy 仓库中回源成功后落盘的缓存对象；与之相对的负缓存（对“不存在”结果的缓存）不在第一期迁移范围内。 |
| 单飞合并 | 同一 proxy 仓库同一路径的并发缓存未命中只发起一次有效上游拉取，其余请求等待并共享结果。 |
| 幂等键 | 由稳定源标识、目标路径和内容校验构成的键，用于迁移重跑时精确识别已一致对象并计为跳过。 |
| 停写窗口 | 在线迁移切换前源端 Nexus 停止写入或转为只读的时间窗口，用于执行最终增量扫描并消除漂移。 |
| 漂移 | 在线迁移期间源端发生的新增、修改或删除，导致源与目标不一致的差异项。 |
| 离线迁移包 | 由受支持导出流程生成的完整迁移输入：权威仓库清单、group 成员关系、proxy 上游配置、资产/缓存清单、blob 数据与校验信息，同属一个一致性快照。 |
| 裸 blob store | 只有 Nexus blob 数据、缺少权威仓库清单与配置的输入；只允许明确降级的尽力恢复，任务总状态不得标记为全量成功。 |
| 尽力恢复 | 对裸 blob store 仅迁移能明确归属到 Raw/Maven/npm 路径的内容，不猜测上游凭据与成员关系的降级模式。 |
| ACL | 仓库级访问控制列表，第一期至少支持 read、write、admin 三类动作。 |
| API Token | 用户签发的长期凭据，用于 CLI 与自动化客户端；明文仅签发时显示一次，持久化只存哈希。 |
| 会话撤销 | 服务端持有的会话失效状态或版本，保证退出、禁用等操作提交成功后的下一次请求必定失败。 |
| packument | npm 协议中的包级元数据文档，包含版本集合、dist-tag 与 tarball 地址。 |
| dist-tag | npm 包的发布标签（如 latest），group 合并与迁移必须按既定规则处理其冲突。 |
| checksum sidecar | Maven 布局中与构件同路径存放的校验和伴随文件（如 .sha1、.md5）。 |
| 参数快照 | 迁移任务启动时固化的不可变参数副本，含冲突决策，落库后不随后续配置变化。 |
| 对象检查点 | 迁移过程中按单对象原子提交边界记录的进度点，支撑暂停、取消、中断后的幂等续传。 |
| 有界失败样本 | 迁移报告中数量受限的失败明细记录，超出部分只计数并注明省略数量，防止报告无限膨胀。 |
| 显式排除（放弃） | 管理员在迁移计划或执行中显式将仓库/对象排除出迁移范围的决策，两词同义；存在任何显式排除时任务不得标记全量成功，被排除项保留在报告中。 |
